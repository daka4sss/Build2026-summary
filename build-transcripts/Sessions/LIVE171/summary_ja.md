## 全体像

本セッションは約13分間のライブトークであり、Marco Casalaina と Ayca Bas が Microsoft Build 2026 で注目を集めた「IQ」シリーズのコンセプトと実装を解説する。セッションタイトルは「Three IQs」だが、冒頭で Marco が「IQ は三つだったが、今は四つになった」と宣言し、**Web IQ・Foundry IQ・Fabric IQ・Work IQ** の四つのサービスが正式な構成として紹介されている。

IQ の根本的な目的は「コンテキストの腐敗（context rot）の防止」である。現実世界のデータは構造化データ・非構造化データ・メールや Teams メッセージなどの人間的コンテキストに分散しており、エージェントがその都度すべてのコンテキスト情報を自前で持つのは非効率かつ維持困難になる。各 IQ はそれぞれのデータドメインへのエージェント的なアクセス機構を提供することで、個々のエージェントが同じコンテキスト情報を重複保持する手間を省く。

セッションでは、四つの IQ を一つのエージェントに統合したリファンドプロセッサーエージェントのデモを通じて、ツール選択の制御方法、エージェントへの命令記述のノウハウ、Microsoft 365 上でエージェントに独立したアイデンティティと固有のセキュリティコンテキストを持たせる仕組みまで踏み込んで紹介している。

## チャプター 1: 四つの IQ の概要と役割分担（00:00頃）

Ayca Bas は現実のデータ環境について「デモでは自分の好きなデータソースを使えるが、実際のデータはあちこちに散らばっている。ファイル、構造化データ、非構造化データ、そして人間のコンテキストが混在している」と指摘し、IQ シリーズがそれらを束ねてエージェントに接続するためのサービス群だと説明した。

Marco Casalaina が四つの IQ を次のように定義した。

- **Web IQ** — エージェントをウェブ全体の知識に接続する。出荷遅延の確認やローカル情報の取得など、リアルタイムのウェブ情報が必要な場面で機能する。
- **Work IQ** — Microsoft 365 のデータ（メール、Teams メッセージ等）をエージェントに接続する。
- **Fabric IQ** — 主に**構造化データ**向け。人間であれば Power BI レポートでアクセスするようなデータを、エージェントがヘッドレスかつエージェント的な方法で取得できるようにする。エージェントが構造化データにアクセスするための「エージェンティック・フェース（agentic face）」を提供する。
- **Foundry IQ** — 主に**非構造化データ**向け。Blob ストレージ、検索インデックス、SharePoint などが対象。三年前から存在するシンプルな RAG（Retrieval-Augmented Generation）ではなく、**エージェンティックな検索（agentic retrieval）** を実現する仕組みである。Marco は「三年も経てばこの業界では古典だ」と述べ、従来型 RAG との差別化を強調した。

二人はこのセッションに向けてこれらの IQ を組み込んだエージェントをペアプログラミングで構築したと明かした。

## チャプター 2: エージェント命令の設計と IQ のツール選択制御（03:00頃）

四つの IQ をエージェントのツールとして登録するだけでは、エージェントが適切なタイミングで適切な IQ を呼び出す保証はない。Ayca Bas はこの問題に対して**エージェント命令（agent instructions）の徹底的な作り込み**が鍵だと解説した。

デモで使用した命令には以下が含まれていた。
- 各 IQ の役割と使用タイミングの明確な説明
- Fabric IQ 向けのデータマッピング定義
- Work IQ を使うときの検索ルール、およびメール送信などのアクション実行時に従うべきルール
- Work IQ がクエリを受け取ったときに変換するべき JSON の出力形式のサンプル
- Web IQ の使用に関するルール

Ayca は「ただプラグインして試すだけでも動くことはあるが、IQ から本当に良いパフォーマンスを引き出すには命令の調整が必須」と述べた。また、「これらのサービスはまだ非常に新しく、早期段階にある」とも明言しており、ユーザー側での命令チューニングが現時点では重要なことを率直に伝えた。なお、この命令ファイルは **Copilot CLI** を活用して作成したと Marco が補足した。

Marco はこれを総括して「IQ の主な目的の一つはコンテキストの腐敗（context rot）を防ぐことであり、各エージェントが同じデータコンテキストを個別に抱え込まなくて済むようにすること」と定義した。ただし IQ の採用はすべての命令記述を免除するわけではなく、どのツールをいつ呼ぶかの指定は引き続きエージェント開発者の責任として残ると強調した。

## チャプター 3: エージェントテンプレートと独立アイデンティティ（05:29頃）

Marco は Foundry ポータル上で構築したリファンドプロセッサーエージェントを、さらに **Microsoft 365 のエージェントテンプレート（agent template）** として公開したデモを披露した。この仕組みが、セッションで「キーノートで少し過小評価されていた」と述べた目玉機能である。

エージェントテンプレートから**エージェントインスタンスを作成する**と、単なるエージェントを作るのではなく「自分専用のエージェント（my agent）」を持つことになる。具体的には次の特徴を持つ。

- **組織図（org chart）に登場し、特定のユーザーへのレポートラインが設定される**
- **専用の Teams ボックス（チャットチャンネル）を持つ**
- **固有のメールアドレスと受信ボックスを持つ**

Marco はデモの中で「このエージェントに『メールで苦情がないか確認してくれ』と指示したとき、私のメールではなくエージェント自身のメールを確認しに行く」と説明した。エージェントは顧客の Maria Garcia に返信メールを送り、Marco にも CC を入れるという動作を実際に示した。

この独立アイデンティティ設計は**セキュリティの観点から特に重要**である。Marco が紹介した「ClawPilot」（社内ツール、Work IQ を多用）の例では、エージェントがユーザーの代理（on behalf of）として動作するため、ユーザーが持つすべての権限をエージェントも行使できてしまう。これは常に望ましい挙動ではない。独立したセキュリティコンテキストを持つエージェントであれば、「メールや Teams メッセージの送信は許可するが、OneDrive からの削除は不可」といった細かい権限設定が可能になり、組織へのデプロイにおいて適切なセキュリティポスチャを設計できる。

## チャプター 4: 実行トレースと IQ シリーズのリソース案内（09:01頃）

Ayca は、Marco が Microsoft 365 エージェントとのチャットを実演している間、バックグラウンドで四つの IQ がどのように協調動作していたかをトレース画面で示した。Work IQ → Fabric IQ → Foundry IQ の順に呼び出され、「Maria Garcia のパッケージを発見、返金ポリシーを確認、返金を実行、Maria にメール」という一連の流れが**同期的に（synchronously）** 実行されていたことが可視化された。

セッションの締めくくりとして、Marco は IQ についてさらに深く学べるリソースを紹介した。

- **IQ シリーズ（IQ series）**: `aka.ms/iq-series` でアクセス可能
- Foundry IQ と Work IQ のエピソードはすでに公開済み
- Fabric IQ と Web IQ のエピソードは近日公開予定
- クックブックの完了と全エピソードの視聴で**デジタルバッジ**を取得でき、IQ 初期エキスパートとして認定される

## まとめ

### セッション全体の結論

本セッションは、Microsoft Build 2026 で注目を集めた「IQ」シリーズ（Web IQ・Foundry IQ・Fabric IQ・Work IQ）の全体像をライブデモとともに解説した短時間（約13分）の濃密なセッションである。IQ の本質は「コンテキストの腐敗防止」であり、エージェントがデータソースごとのコンテキストを個別に抱え込む非効率を解消する。さらに Microsoft 365 のエージェントテンプレート機能を通じてエージェントに独立したアイデンティティとセキュリティコンテキストを与えることで、組織レベルの安全なエージェント展開が可能になるという方向性が示された。

### 発表された新機能・取り組み（ステータス）

| 機能・取り組み | 内容 | ステータス |
|---|---|---|
| **Web IQ** | エージェントをウェブ知識に接続するツール。リアルタイム情報取得に対応 | 発表済み（Early Stage） |
| **Work IQ** | Microsoft 365（メール・Teams 等）のデータをエージェントに接続 | 発表済み（Early Stage）、IQ シリーズエピソード公開済み |
| **Fabric IQ** | 構造化データへのヘッドレス・エージェンティックアクセスを提供 | 発表済み（Early Stage）、IQ シリーズエピソード近日公開予定 |
| **Foundry IQ** | 非構造化データ（Blob・検索インデックス・SharePoint 等）向けエージェンティック検索 | 発表済み（Early Stage）、IQ シリーズエピソード公開済み |
| **Microsoft 365 エージェントテンプレート** | Foundry で作成したエージェントを M365 上でテンプレート化し、インスタンスに独自 ID・メールアドレス・Teams ボックスを付与 | デモ披露済み（提供開始時期は言及なし） |
| **エージェント固有のセキュリティコンテキスト** | エージェントに独立した権限セットを付与し、ユーザー代理（on behalf of）とは異なる最小権限セキュリティポスチャを実現 | デモ披露済み（アーキテクチャ方針として言及） |
| **IQ シリーズ（aka.ms/iq-series）** | 各 IQ の学習コンテンツ。完了でデジタルバッジ取得可能 | Foundry IQ・Work IQ 公開済み、Fabric IQ・Web IQ 近日公開予定 |

### 技術者向けの次アクション

1. **aka.ms/iq-series にアクセスする** — 公開済みの Foundry IQ・Work IQ エピソードを視聴し、クックブックを完了してデジタルバッジを取得する。
2. **エージェント命令（system prompt）を丁寧に設計する** — 各 IQ の役割、使用タイミング、データマッピング、出力 JSON サンプルを命令に明示し、適切なツール選択を誘導する。IQ はまだ早期段階であるため、命令チューニングが品質に直結する。
3. **Foundry IQ を非構造化データ検索に活用する** — Blob ストレージや SharePoint 上の非構造化コンテンツへのアクセスに、従来型 RAG の代わりに Foundry IQ のエージェンティック検索を検討する。
4. **Work IQ でエージェントに M365 コンテキストを与える** — メールや Teams メッセージの読み取り・送信を必要とするエージェントに Work IQ を組み込み、組織内コミュニケーションデータを活用する。
5. **エージェントのセキュリティポスチャを明示的に設計する** — 組織への展開時は「ユーザー代理（on behalf of）」か「エージェント固有のアイデンティティ（独立セキュリティコンテキスト）」かを意識し、最小権限原則に基づいて権限セットを定義する。
