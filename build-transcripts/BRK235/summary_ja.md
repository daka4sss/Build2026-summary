## 全体像

主題は「**オープンモデルはエージェントの実用フェーズに入った**」という点にある。前半は Michael が Ollama の概要、急速に改善するオープンモデルの能力進化、そして国立研究所や大企業での実際の導入事例を紹介。後半は Parth が、コーディングエージェント（GitHub Copilot CLI）との連携、機密データをローカルで処理する「ハイブリッド実行」、パーソナルエージェント（Open Claw）のセットアップを実機でデモした。最後に会場との Q&A（エッジデバイス、VRAM/ユニファイドメモリ、推論エンジン、推奨モデル）で締めくくられた。

一貫したメッセージは「**データを手元に置いたまま（プライバシーを守りながら）、フロンティアに近い知能を使ってエージェントを動かせる時代になった。難しいタスクはクラウド、機密性の高いタスクはローカルへ、という使い分けがシームレスにできる**」というものである。

## チャプター1: イントロダクション ― Ollama とは何か（0:00頃）

Parth が「Ollama でエージェントを担当している」、Michael が「Ollama の共同創業者の一人」と自己紹介。会場には「Ollama を聞いたことがある人？」の問いに多数が挙手し、認知度の高さがうかがえた。

**Ollama とは**:
- 開発者がオープンモデルに最も簡単にアクセスし、自分のツールと組み合わせて使える手段。
- **1コマンドでモデルを実行**してチャットを始められる。
- 最近導入した `ollama launch` コマンドで、オープンモデルを **お気に入りのツールに直接注入**できる（Claude Code、VS Code、GitHub Copilot など各種ハーネスに組み込む）。
- アプリ開発者向けに **OpenAI / Anthropic API 互換**を提供。Python・JavaScript 向けの SDK もある。
- **当初からエージェント向けに設計**されており、ツール呼び出し（tool calling）、構造化出力（structured outputs）を重点的にテストし、1行でエージェントをセットアップできる。

## チャプター3: Ollama Cloud ― ローカル推論の拡張（2:21頃）

今年から **Ollama Cloud** を追加し、ローカル推論を補完できるようにした。

- **データは学習に使われず、ゼロデータ保持（zero data retention）**。
- データセンターグレードのハードウェアでフロンティアモデルを実行できる。
- ローカルに十分な計算資源がない場合でも、Ollama でスケールして望むモデルを実行可能。
- ユースケース例として **並列エージェント（parallel agents）** ── 小さいモデルでは不可能な難しい作業を実現する ── が挙げられた。
- 各モデルはプロバイダー本来の **最大コンテキストウィンドウ**を備える。
- これは **完全にオプションのサービス**であり、使うかどうかは利用者が選べる。

## チャプター4: オープンモデルの能力進化（3:18頃）

SWE-bench Verified のスコアを「例示目的」で提示しつつ、オープンモデルが **メインストリームのユースケースを大幅に低価格で実現**しつつある点を強調した。

- DNA合成やフロンティアコーディングのような最先端研究ではなく、**一般的なタスク**でオープンモデルが使えるようになってきた。
- ユーザーは自分の目標に合わせてモデルをカスタマイズし、パラメータを調整して実行できる。

**モデル能力の進化の段階**:
1. **純粋な汎用チャット**（過去）
2. **推論能力（reasoning / thinking）**の獲得
3. **個別ツール・複数ツールの利用**
4. **ロングホライズン・タスク（long horizon tasks）** ── 数時間〜数日間動き続けられるタスク。これがちょうど現実になり始めた段階であり、今後さらに多くの解放（unlock）が期待される。

- **NASA グレン研究センター**: クルーの健康・パフォーマンスに関する確率論的リスク評価。Ollama を用いて多様な火星ミッションのタスクを **18の定義済み人間-システムタスクカテゴリ**に分類。

## チャプター7: ライブデモ② ― `ollama launch` と GitHub Copilot CLI 連携（8:16頃）

今年導入した **`ollama launch`** は、好みのツール・アプリにオープンモデルを接続する手段。

- パーソナルエージェント（**Open Claw**、**Hermes**）から、各種エージェント系コーディングハーネスまで対応。
- 対応例として **Claude Code、Codex、Copilot CLI、Droid** などが列挙され、今後さらに拡充予定。

**Copilot CLI デモ**:
- `ollama launch copilot` と打ち、使いたいモデルを選ぶだけ。
- デモではクラウド上の **Kimi K2.6** を使用（ローカルモデルも同様に選べる）。
- Copilot CLI で **取り組む issue を直接選べる**点を評価。「この issue を取得して」と指示 → モデルが思考（thinking が長め）→ issue の内容を正確に把握。
- ターミナルから一切離れずに、オープンモデルで実作業（「この issue を参照する未解決の PR はあるか？」→「なし」→ 修正に着手）を進められる。
- **サブエージェント、Web 検索**などの基盤技術が確実に動くようにしており、複数のサブエージェントを起動してコードベースを探索し、修正案を提示。計画を立てて実行できる。

## チャプター8: ライブデモ③ ― ハイブリッド実行とローカルでの機密処理（10:35頃）

**ハイブリッド実行（hybrid execution）**の重要性を強調。

- Ollama が提供する **フロンティアに非常に近い知能のクラウドモデル**は、難しいコーディングやエージェントタスクに最適。
- 一方、**極めて機密性の高いデータ**はローカルで処理したい。

**クレジットカード明細デモ（ローカル完結）**:
- 毎月末に行うワークフローとして、クレジットカードの明細書（※デモはダミー）を処理。
- ミニマルなハーネス **π（Pi）** を使用。π は **システムプロンプトを肥大化させない**設計で、ローカルモデルに最適。
- MacBook 上でローカル実行する **Qwen 3.6** を使用。「この明細を処理して、カテゴリごとの支出を見せて」と指示。
- モデルが PDF を処理するコードを書き、計算して支出内訳を提示。**情報は一切コンピュータの外に出ない**。
- 「旅行への支出が多いな、そろそろ次の休暇かも」とユーモアを交えつつ、**"good enough"（十分に使える）レベルでローカルモデルが実作業をこなせる**ようになった点を強調。「ここ数カ月で、ローカルモデルが本当に実作業に使えるようになった」。

## チャプター10: Q&A（13:40頃〜）

### Q1. エッジデバイス（モバイル）対応の予定は？（14:14頃）
- iPhone / Android などラップトップほどの性能がないデバイスへの Ollama 統合の予定を質問。
- **回答（Michael）**: まだモバイルデバイスは直接ターゲットにしていない。ただし実験している人はおり、動作はする。Ollama は **Qualcomm Snapdragon デバイス**で有効化済みで、これはモバイルと同じチップセット。現時点では **仕事向けのメインストリームなユースケース**を優先しているため、モバイルは直接の対象外。

### Q2. VRAM / ユニファイドメモリとモデルサイズ・コンテキスト長について（15:30頃）
- デモで 262K コンテキストウィンドウが見えたが、どんなマシン・スペックか、量子化モデルか、という質問。
- **回答（Parth）**:
  - Ollama には推奨の **デフォルト量子化**があり、加えて **MLX サポート**では **NVFP4** で実行できる。
  - 自身は最上位スペックの Mac を使用しており、小さめのモデルなら **フルコンテキスト長**で動かせ、コンパクション（文脈圧縮）をあまり気にせず済む。
  - ローカルでエージェントワークロードを動かすと **ハードウェア制約**にぶつかり最大コンテキスト長を支えられなくなりがち。
  - **ユニファイドメモリ**は、CUDA カードに比べ速度はやや落ちるものの、**大きなメモリでより難しいタスクを扱える**点が利点。時間とともに性能・速度も改善するだろう。
  - **ハードウェアトレンド**: 各社がユニファイドメモリへ移行中。Apple に始まり、**NVIDIA と Microsoft が発表した RTX Spark は最大128GB のユニファイドメモリ**、**AMD の Strix Halo プラットフォームも最大128GB**まで対応。各ハードウェアチームがユニファイドメモリへ向かっている。

### Q3. Apple Silicon と推論エンジン ― まだ llama.cpp を使っているか？独自エンジンの予定は？（17:37頃）
- **回答（Parth）**: **独自の MLX 推論エンジンを持っている**。Apple デバイスなら **MLX エンジンの利用を強く推奨**（より高速）。利用にはモデルレジストリから MLX モデルを pull するだけ。

### Q4. 128GB MacBook で最良のコーディングモデルは？（18:17頃）
- **回答（Parth）**: お気に入りは（記憶があいまいとしつつ）"1362070"（※聞き取り不明瞭。Qwen 系の特定モデルと推測）と **Gemma**。これらをペアで使い、小さめのスクリプトを書かせている。意外と侮れないのが **gpt-oss 120B**（"GB2SS120B" は gpt-oss-120B と推測）で、スクリプティングなどに有効。
- **補足（Michael）**: **Gemma 4 の dense モデル**は非常に高性能で、フルコンテキスト長でも動かせる。

### Q5. どのモデルを選ぶべきか？（19:00頃〜）
- **回答（Parth）**: タスク次第。コーディング、パーソナルエージェント、チャット、分類などで得意なモデルは異なる。
  - 最良の方法は **いろいろ試すこと**。
  - 今後、`ollama launch` で特定のハーネスを使う際に、**そのシステムに最適な最新モデルの推奨**を表示できるようにしていく予定。
  - 独自アプリを作るなら、複数を試し、ベンチマークして、最も好みのものを選ぶのが一番。

## まとめ

### セッションの結論

- **オープンモデルはエージェントの実用段階に入った** ── メインストリームのタスクなら、フロンティアに近い知能を低コストで使える。
- **ローカル × クラウドのハイブリッド**が鍵 ── 難しい作業はクラウド、機密データはローカル、という使い分けを **同一の体験**でシームレスに行える。
- **プライバシー**が大きな差別化要因 ── データを手元に置いたままエージェントを動かせる（ゼロデータ保持の Ollama Cloud、ローカル完結のπ/Open Claw デモ）。
- **ハードウェアの進化（ユニファイドメモリ）**がローカル実行を後押し ── RTX Spark、Strix Halo など128GB級が登場し、より難しいタスクをローカルで扱えるようになる。

### 発表・言及された製品・モデル

- **Ollama**: オープンモデルをローカルで実行するプラットフォーム。800万人超の開発者が利用。
- **`ollama launch`**: オープンモデルを Claude Code / Copilot CLI / Codex / Droid / Open Claw / Hermes などのツールに注入するコマンド。
- **Ollama Cloud**: ゼロデータ保持でフロンティアモデルをデータセンターグレードのハードで実行。並列エージェント対応。今年導入。
- **MLX 推論エンジン（Ollama 独自）**: Apple デバイス向けに高速。NVFP4 量子化対応。
- **Gemma 4 12B（統合モデル）**: Google DeepMind が会期当日朝に発表、Ollama で即利用可能（GA レベルの言及）。Gemma 4 dense モデルも高性能と評価。
- 言及されたモデル: **Kimi K2.6**（クラウド）、**Qwen 3.6**（ローカル）、**gpt-oss 120B** など。
- 連携ハーネス: **GitHub Copilot CLI、Claude Code、Codex、Droid、π（Pi）、Open Claw、Hermes**。
- ハードウェア: **NVIDIA / Microsoft RTX Spark（最大128GB ユニファイドメモリ）**、**AMD Strix Halo（最大128GB）**、**Qualcomm Snapdragon**（モバイル系チップ、Ollama 動作可）。
