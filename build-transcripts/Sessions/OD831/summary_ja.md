## 全体像

本セッションは、Azure API Management（APIM）が「従来のAPI管理」から「AIモデル・ツール・エージェントを横断するユニバーサルゲートウェイ」へと進化した姿を、デモを交えて紹介するものである。Gartnerの予測では2028年までに95%超の企業がLLM/GenAI APIを本番環境で利用するとされており、コスト管理・セキュリティ・スケーラビリティ・可観測性といったAPIガバナンスの課題がAI領域では一段と複雑化している点が問題提起として示された。

Azure API Managementはこれらの課題に対し、従来のAPIゲートウェイ機能と新たなAIゲートウェイ機能を組み合わせ、モデル（Azure AI Foundry、OpenAI、Anthropic、AWS Bedrock、Google Vertex AI等）・ツール（MCPサーバー、REST API）・エージェント（A2Aプロトコル）という三層すべてをカバーするガバナンス基盤として機能する。

セッションは「モデルガバナンス」「ツールガバナンス」「エンタープライズカタログ（Azure API Center）」「エージェントガバナンス」の4テーマに分かれ、各テーマでデモとGA/Previewアナウンスが行われた。

## チャプター1: セッション紹介とAI時代のAPIガバナンス課題（0:00頃）

### 背景

登壇者のAnishがセッション冒頭でAPIManagementチームを代表して登壇し、本日の構成（モデルガバナンス→ツールガバナンス→エンタープライズレジストリ→エージェントガバナンス＋各デモ）を説明した。

Gartnerの統計として「2028年までに95%超の企業がLLM/GenAI APIを本番で利用する」という数字を挙げ、AI本番化に向けて企業が直面する課題を整理した。

- **コスト管理**: トークン消費のコントロールと組織ポリシーへの適合
- **エージェント増殖**: 数百から数千、さらには数百万規模に達し得るエージェントの管理
- **セキュリティ・安全性**: システムとアプリケーションの保護
- **モニタリングとトラブルシューティング**: AI系システムの可視化
- **開発者速度**: 開発者が優れたAIシステムを素早く構築できる環境の整備

これらの課題は従来のAPIガバナンスと本質的に同じだが、AI領域では問題が大幅に複雑化・拡大することが強調された。

### Azure API Managementプラットフォームの構成

API Managementプラットフォームは2製品で構成される。

1. **Azure API Management（ゲートウェイ）**: マネージドゲートウェイ（＋セルフホステッドゲートウェイ）。APIの安全な公開・管理・分析を担う。
2. **Azure API Center（カタログ）**: 組織内のAPIを種類・場所を問わず追跡・発見・ガバナンスするカタログ。

### AIゲートウェイとしての拡張

従来のAPIゲートウェイ機能に加え、以下を包含する「ユニバーサルゲートウェイ」へと進化している。

- **モデルゲートウェイ**: Azure AI Foundry、OpenAI、Anthropic、AWS Bedrock、Google Vertex AI、Hugging Face等あらゆるモデルプロバイダーに対応
- **ツールゲートウェイ**: MCPエンドポイント、OpenAPI仕様、カスタムコネクター
- **エージェントゲートウェイ**: A2A（Agent-to-Agent）プロトコル対応

AIゲートウェイが提供する横断的機能:
- **ガバナンス**: 拡張ポリシーセット（トークンレート制限・クォータ、承認済みモデル/MCPサーバー/スキル/プラグイン/A2Aエージェントのカタログ）
- **セキュリティ・安全性**: OWASP API Top 10対応、クライアント認証・認可、キーレス管理ID、クレデンシャルマネージャー、プロンプト・コンプリーションのモデレート、PII漏洩防止
- **可観測性**: ログ・メトリクス・トレーシング、トークン消費追跡、プロンプト/コンプリーションのログ、MCPツールインタラクションのログ、エンドツーエンドのエージェント相互作用のトレーシング
- **スケーラビリティ**: セマンティックキャッシング、プロビジョニング容量へのルーティング優先化、モデルフォールバック、SSE/ストリーミングHTTPプロトコル対応
- **開発者速度（Velocity）**: 開発者ポータル、VS Code拡張機能、Copilotによるポリシー生成、MCPプロトコル用テストコンソール

## チャプター3: モデルガバナンス デモ — AWS BedrockモデルへのポリシーApply（11:33頃）

Mikeによるライブデモ。

### デモ内容

AWS BedrockにデプロイされたモデルをAPI Managementにインポートし、2つのポリシーを適用。

1. **トークンレート制限ポリシー**: ユーザーごとに1分間10トークンに制限。
2. **コンテンツ安全性ポリシー**: 有害なコンテンツをブロック。

デモシナリオ:
- 第1リクエスト: 「Azure API Managementを10語で説明して」→ 成功し正常なレスポンスを受信。
- 第2リクエスト: 同様のリクエスト→ **トークンクォータ超過により429スロットリングで失敗**。AIゲートウェイがバックエンドに到達する前にブロック。
- コンテンツ変更: プロンプトを「I hate you（憎しみの表現）」に変更→ **コンテンツ安全性ポリシーによりブロック**。モデルには到達しない。

### 新機能アナウンス（GA）

**AnthropicおよびVertex AIモデルへのLLMポリシー適用 — GA（2026年6月より）**

今月（2026年6月）から、以下が利用可能になった。
- Anthropic Messages APIを使用したAnthropicプロバイダーのモデル（Claudeモデル）に対して、トークンレート制限、トークンメトリクス、コンテンツ安全性、セマンティックキャッシング等のLLMポリシーを適用可能。
- Google Cloud上のVertex AIモデルにも同様に対応。
- これらのモデルのログ・メトリクス収集も可能。
- API ManagementにてMicrosoft FoundryインポートでClaudeの操作をインポート可能。

**追加トークンメトリクス機能 — GA**

`llm-emit-token-metric` ポリシーの拡張により、コンプリーショントークン・プロンプトトークンだけでなく、**thinking（思考）トークン、reasoningトークン、キャッシュトークン**等のあらゆるトークンタイプのメトリクスも収集可能に。Application Insightsにメトリクスを転送し、アラート設定やより正確なコスト管理ダッシュボードを構築できる。

**Unified Model API — Public Preview**

単一のAPIエンドポイントで複数バックエンドモデルプロバイダーを抽象化する新機能。

- 現在対応: Anthropic Models（Messages API）、OpenAI互換モデル（Chat Completions API）
- クライアントはChat Completions API形式で統一してアクセス可能。API ManagementがAnthropicの形式へ自動変換する。
- **エイリアス機能**: バックエンドとクライアントのモデル名を分離できる。例: 「GPT」というエイリアスを作成しGPT 5.3にマップ→後からGPT 5.4にアップグレードしても、さらにAnthropicのClaudeに切り替えてもクライアントへの影響ゼロ。
- プロバイダー横断のフォールバック設定: OpenAIのGPTモデルからAnthropicのClaudeモデルへのフェイルオーバーをAPI Managementが自動変換して実現。

**Bring Your Own Model（BYOM） — GA（Microsoft Foundry）**

AI Gatewayプロキシ経由（Azure API Managementまたはサードパーティの Chat Completions API互換ゲートウェイ）で任意のモデルをMicrosoft Foundryに追加できる機能。Foundry Agent Serviceでのエージェント・プロンプト構築に利用可能。

## チャプター4: ツールガバナンス — 概要とMCP対応機能（16:35頃）

AnishがモデルガバナンスのMikeから引き継ぎ担当。

### ツールとは何か

ツールとは、エージェントやLLMが「知性を行動に変換する」ために接続するAPIやMCPサーバーのことである。LLMが知性を提供し、ツールが実際のアクション（例: データ取得、決済処理、チケット作成等）を担う。

### ツールガバナンスの課題

- 企業は数十年にわたりAPIとツールの大規模ポートフォリオを構築してきた。これをAI新時代にどう再活用するか。
- ツールを追加するほどリスクは指数関数的に拡大する（セキュリティ・コンプライアンス・パフォーマンスの課題）。

### Azure API ManagementのMCPサーバー対応機能

**MCPサーバーの作成**
- 既存のREST API資産をMCPサーバーへ数クリックで変換可能。コードの書き直し不要。
- 任意のHTTPバックエンドを1分未満でMCPサーバーとして公開可能。

**既存MCPサーバーのプロキシ**
- 自社MCP（ファーストパーティ）も他社MCP（サードパーティ: Stripe、Jira、Atlassian、Box、Neon等）もAPI Managementでプロキシ可能。
- 同一のガバナンスポリシーとセキュリティ境界を適用。

**MCPサーバーの保護**
- クレデンシャルマネージャーとポリシーによりAPI KeyやOAuth等の認証を簡素化。
- サブスクリプションキーによるアクセス認証も設定可能。

**ポリシーの適用**
- コンテンツ安全性（PII漏洩防止等）
- スロットリング（エージェント/LLMによるツール乱用防止）

**可観測性**
- ツールコールのログ・トレース・メトリクスを提供。
- リクエストの発生からAPIゲートウェイ通過、MCPサーバーへの到達まで、どのツールが呼ばれどの認証が使われたかを完全にトラッキング。

### 新機能（最近リリース済み）

**MCP to Products（MCPをProductsコンセプトに追加）**
- 1つ以上のMCPサーバーをAPI Management Productsにバンドル可能になった。
- Productに対してサブスクリプション・クォータ・承認ワークフローを設定可能。

**MCPバージョニング**
- MCPサーバーに複数バージョンを作成可能。
- A/Bテスト、Blue/Greenデプロイメント、本番環境と開発環境の並列管理に活用可能。

**MCPツールの高精細可観測性**
- Open Telemetryでメトリクス・トレース・ログを提供。
- クライアント発生からAPIゲートウェイ、MCPサーバーまでのエンドツーエンドメトリクスをトラッキング。

**Management APIによるMCPの自動化**
- MCPをManagement API（REST API）のファーストクラス要素として追加。
- ポータルを介さずREST API経由でMCPの作成・保護・ポリシー適用を自動化可能。

## チャプター6: ツールガバナンス デモ2 — エージェント設計時のツールディスカバリー（25:28頃）

Mikeによる「プロトタイプ」デモ。AI GatewayがGitHub Copilotと連携してエージェント設計時にツール発見を支援するフローを紹介。

### デモのシナリオ

開発者の意図: 「オンライン注文の送料を計算するエージェントを作りたい」

### フローの説明

1. **意図入力**: 開発者がGitHub Copilot CLIにシンプルな意図文を入力。
2. **ツール発見**: Copilot CLIがAI GatewayのMCPサーバーにクエリを発行し、利用可能なツールを自動発見。
3. **自動選別**: 意図に関係するツール（「注文参照」「国内送料計算」「国際送料計算」）を自動選択。無関係なツール（「天気予報」等）を除外。
4. **確認**: 開発者が選択されたツールをレビューし確認。
5. **エージェントコード生成**: CopilotがGitHub Copilot SDKを使用して完全なエージェントコードを自動生成。ツール定義とツール間のチェーニングロジックもツールメタデータから導出済み。
6. **デプロイ**: エージェントはローカル実行またはFoundryへの直接デプロイが可能な状態。

### 技術的な仕組み

- 軽量カスタムスキルがGitHub CopilotをAI Gatewayに接続し、ツール発見とエージェントコード生成を可能にする。
- GitHub Copilot CLIはAI GatewayのMCPサーバーを設定し、AI Gateway経由で公開されるすべてのツールの発見エンドポイントとして機能する。
- デモでのAI Gatewayは、API ManagementとAPI Centerの機能を統合した「Foundryネイティブ、マルチテナント、常時稼働コンポーネント」となる予定のもの（デモ時点ではスタンドアロンのAPI ManagementとAPI Centerリソースでモック実装）。
- API CenterはAPI Managementから自動同期されたすべてのツールを含むMCPサーバーを公開する。

### 今後の開発予定（プロトタイプ中）

- AIゲートウェイによるエージェント**実行時（ランタイム）**のツール動的選択（設計時だけでなく）。
- すべてのモデルコールをAI Gateway経由でルーティングし、トークン消費制限などのガバナンスポリシーを適用。

## チャプター7: エンタープライズカタログ — Azure API Center for AI Assets（28:20頃）

Sreekanth Thirthalaが担当。

### 背景と課題

企業がAI投資を拡大するにつれ「エージェント、スキル、MCPサーバー、モデルをどう管理し、チームが発見でき、品質を確保し、重複を防ぐか」という問題が浮上している。

### Azure API Center: エンタープライズカタログ

Azure API Centerはすべての組織AIアセットのエンタープライズカタログであり、単一の正規システム（Single System of Record）として機能する。

**カバーするアセットタイプ（4種）**:
1. REST APIs
2. MCPツール、スキル、プラグイン
3. モデル
4. エージェント

**カタログの最新化**:
- ポータル・CLI・GitHubリポジトリとの直接同期によって登録・更新。
- 手動ドリフトなし。新しいコミットが行われるとアセットが自動更新。

**品質評価（LLM as a Judge）**:
- LLMをジャッジとして使用し、スキルをドキュメントの明瞭さ・パラメータ設計・安全性の観点で評価。
- 開発者とエージェントが消費するものを信頼できる品質基準で管理。

**エージェント向けマーケットプレイス**:
- API CenterはマーケットプレイスエンドポイントをData Plane API経由で公開。
- Claude CodeやCopilot CLIなどの開発ツールが企業スキル・プラグイン・MCPサーバーをカタログから直接発見・ロード可能。

全てAzure、他クラウド、オンプレミス、サードパーティSaaSにまたがって機能する。

## チャプター8: エンタープライズカタログ デモ — スキル・MCP・プラグインの登録と品質評価（30:07頃）

Speaker 1（ナレーションによるデモ）と Sreekanthによるデモ。

### デモ内容1: スキルの登録

1. API Centerポータルの「Register a Skill」からスキルを登録。
2. スキルの能力・ユースケース・動作の詳細を入力。
3. スキルのソースコードのGitリポジトリURLを指定。
4. 例として「コードレビュースキル」をAPI CenterアセットカタログにGitリポジトリURL付きで追加。

### デモ内容2: Gitリポジトリ連携による自動同期

- API CenterとGitリポジトリを統合することで、スキルの追加・更新が自動的にカタログに反映。
- Azure Skills GitリポジトリをAPI Centerに接続するデモを実施。Gitリポジトリ同期後、AzureスキルがAPIアセットとして自動インポートされ、エンタープライズ全体で発見可能に。
- 例: 「Azure Cloud Migrate スキル」（クロスクラウドワークロードのAzure移行を評価・実行するエージェント向けスキル）をカタログから検索・詳細確認。スキル定義にはリファレンスドキュメント・一般的タスク・入出力の定義が含まれる。

### デモ内容3: スキルの品質評価（LLM as a Judge）

API CenterはLLM-as-a-Judge技術を使用したAIスキル評価機能を提供。デフォルトで4つの評価基準（各1〜5スケール、デフォルト閾値3）:

1. **ドキュメントの明瞭さ（Documentation Clarity）**: スキルの目的と動作がどれだけ明確に伝えられているか。
2. **ヘルプの完全性（Help Completeness）**: 出力が包括的なスタンドアロンリファレンスとして機能するか。
3. **発見可能性（Discoverability）**: 機能がどれだけ容易にナビゲート・発見できるか。
4. **安全な使用（Safe Usage）**: 安全な操作のための十分なガイダンスが提供されているか。

評価レポートにはpass/failステータス・各次元スコア・実行可能なフィードバックが含まれる。LLMスコアに加え、構造チェック（有効なフロントマター、スキル名、本文内容）とスキーマ検証（例やエラーハンドリング等のセクション欠落のフラグ）も行われる。

エンタープライズのプラットフォーム管理者は組織固有の基準・コンプライアンス要件・ガバナンスポリシーに合わせたカスタム評価基準を追加定義可能。

### デモ内容4: MCPツールの登録と発見

- GitリポジトリをAPI Centerと統合することでMCPツールを自動登録・最新状態を維持。
- デモでは「Azure MCPサーバー」をGitリポジトリ同期でAPI Centerにインポートし、完全に登録・発見可能なアセットとして即座に利用可能になる状態を確認。
- API Centerポータルの組み込みMCP Inspectorで、MCPサーバーを発見・ツールの入出力を確認・リアルタイムでテスト実行が可能。コードを書かずに操作可能。
- 例: API Center Data Plane MCPサーバーを使用して、カタログ内の全MCPツール一覧の取得や特定サーバーの検索を実演。

### デモ内容5: プラグインの登録と発見

プラグインは、対応AI開発ツールを強化する自己完結型の拡張であり、カスタムコマンド・エージェント・フック・MCP統合をCopilot CLI、Claude Code等に追加する。

1. API CenterのPlugin登録フォームでタイトル・サマリー・説明を入力。
2. バージョン指定。
3. スキルとMCPサーバーをプラグイン内にバンドル可能。
4. 登録されたプラグインはポータルでAPIs・スキル・MCPサーバーと並んで一覧表示される。

**Data Plane APIによる統合**:
- API CenterはData Plane API経由でマーケットプレイスエンドポイントを公開し、プラグインをClaude CodeやCopilot CLIに直接サーフェスする。
- Copilot CLIにエンドポイントを一度登録すれば、フルプラグインカタログが即座に利用可能に。CLIから直接ブラウズ・選択・接続が可能で、開発ワークフローの摩擦を大幅削減。

## チャプター9: エージェントガバナンス — A2Aサポート GA発表（37:01頃）

Sreekanthが担当。

### 背景

エージェントの増殖に伴い、バックエンドへの無媒介・無制限なアクセスはスケールしない。ユーザー・アプリ・エージェント・Copilotが呼び出すA2A、REST、HTTPバックエンドがあらゆるクラウドとオンプレミスに広がっている。信頼できる中間層が必要であり、それがAI Gatewayである。

AI Gatewayが提供する5つの機能: ガバナンス、スケーラビリティ、安全性・セキュリティ、可観測性、開発速度。

### 新機能アナウンス（GA）

**A2A（Agent-to-Agent）サポート in Azure API Management — GA（本日より）**

A2Aはマルチエージェントアーキテクチャのバックボーンとなっており、本日よりA2Aエージェントを従来のREST APIと同じエンタープライズグレードの管理下に置くことができる。

**GA内容**:
- **ガバナンス・セキュリティ・可観測性**: A2AエージェントAPIに対して、他のAPIと同じポリシー（スロットリング、IPフィルタリング、コンテンツ安全性等）を適用可能。
- **エージェントカードとランタイムオペレーション**: エージェントカードのエクスポーズとランタイム操作が可能。
- **Open Telemetryトレーシング**: GenAIセマンティック規約を使用したOpen Telemetryトレースのロギング。標準化された深い可視性を実現。
- **アセットのインベントリと公開**: エージェントのAPIとしての登録・発見が可能。
- **シンプルな登録フロー**: A2Aエージェントの登録がシンプルになり、エージェントカードやエージェントURLといったエージェント固有のメタデータがライフサイクル・デプロイ詳細と並んでネイティブに表示される。

## まとめ

### セッションの結論

本セッションで発表されたすべての機能は本日より利用可能である（詳細: `aka.ms/apim/blog`）。

Azure API Managementは、従来のAPIゲートウェイを超えて、AIモデル・ツール（MCPサーバー）・エージェント（A2Aプロトコル）をエンタープライズグレードで一元管理できるユニバーサルゲートウェイへと進化した。企業はこの一つのプラットフォームで、マルチクラウド・オンプレミスにまたがる全AI資産のコスト管理・セキュリティ・コンプライアンス・可観測性を実現できる。

### 発表新機能一覧

#### Generally Available（GA）— 本日より利用可能

- **AnthropicおよびVertex AIモデルへのLLMポリシー適用（GA）**: トークンレート制限、コンテンツ安全性、セマンティックキャッシング等をAnthropicのClaudeモデルとGoogle Vertex AIモデルに適用可能（2026年6月〜）
- **追加トークンメトリクス機能（GA）**: thinking/reasoning/キャッシュトークン等あらゆるトークンタイプのメトリクス収集（`llm-emit-token-metric`ポリシーの拡張）
- **Bring Your Own Model（BYOM）in Microsoft Foundry（GA）**: AI Gateway（APIM等）でプロキシしたモデルをFoundryに追加しFoundry Agent Serviceで利用可能
- **A2A（Agent-to-Agent）サポート in Azure API Management（GA）**: A2Aエージェントをエンタープライズグレードの管理・ガバナンス下に置く。エージェントカード、Open Telemetryトレーシング（GenAI規約）、ポリシー適用、インベントリ管理を含む
- **MCP to Products**: MCPサーバーをProductsにバンドルしサブスクリプション・クォータ・承認ワークフローを適用
- **MCPバージョニング**: MCPサーバーの複数バージョン管理（A/Bテスト、Blue/Greenデプロイ）
- **MCP向け高精細可観測性**: Open Telemetryによるエンドツーエンドメトリクス・トレース・ログ
- **Management APIによるMCP自動化**: MCPをManagement REST APIのファーストクラス要素として対応

#### Public Preview（プレビュー）

- **Unified Model API（Public Preview）**: 複数バックエンドプロバイダー（Anthropic Messages API、OpenAI Chat Completions API等）を単一APIとして抽象化。エイリアス機能（バックエンドとクライアントのモデル名分離）、プロバイダー横断フォールバックを含む

#### デモ・プロトタイプ（開発中）

- **エージェント設計時のツールディスカバリー**: GitHub Copilot CLIとAI GatewayのMCPサーバーが連携し、開発者の意図からツールを自動選択しエージェントコードを生成（デモ段階）
- **エージェントランタイム時の動的ツール選択**: 設計時だけでなく実行時にもAI Gatewayがツールを動的に選択（プロトタイプ中）
