## 全体像

本セッションでは、Microsoft Fabric向けの新しいアプリケーション開発バックエンドフレームワーク「**Rayfin**」が紹介された。Rayfinは、エージェントによるコーディング時代のバックエンドとして位置づけられており、TypeScript SDK + CLI を使ってデータベース・関数・ストレージ・アクセスポリシーをすべてコードで定義し、`rayfin up` コマンド一発でMicrosoft Fabricへデプロイできる。

セッションは大きく3つのパートで構成される。まず共同ホストのBenとSachinがRayfinの基本アーキテクチャとデモを実演し、次にPower BIチームのSujataがデータアプリテンプレートを用いた分析アプリ構築を示し、最後にReplitのCarlがノーコード寄りのユーザー向けの統合を発表した。

Rayfinは現時点でGitHub（github.com/microsoft/rayfin）にて試用可能で、Fabricを無料で使い始めることもできる。今後、PostgreSQLサポート・RBAC・追加データコネクタ・OIDC認証・リアルタイムサービス・永続無料ティアなどが順次追加される予定であることが述べられた。

BenとSachinが登壇し、エージェントによるコーディング（agentic coding）がアプリ開発を民主化していると紹介。Benはコーチをしているサッカーチームのコーチ仲間「Brent」が、エンジニアでないにもかかわらずエージェントコーディングを使って試合統計アプリやスナックスケジュールアプリを作り始めた例を挙げ、「ビルダー」の裾野が広がっていると語った。

## チャプター2: Rayfinとは何か（2:30頃）

Rayfinの定義：

- AIコーディング時代のための**エンタープライズバックエンドフレームワーク**
- TypeScript SDK と CLI で構成され、人間とエージェントの両方がバックエンド全体をコードで定義できる
- 定義対象: データベース（テーブル・スキーマ）、サーバーレス関数、ストレージ、アクセスポリシー
- `rayfin up` コマンド1つで Microsoft Fabric へデプロイし、エンタープライズグレードのセキュリティとコンプライアンスが自動付与される

Sachinによる技術解説（約8:15頃）:

**エンティティ定義（TypeScript）**:
- クラスに `@entity` デコレーターを付与することでFabricのデータベーステーブルとして認識される
- `@property` デコレーターで列の型・min/maxなどの制約を指定でき、SQLのカラム制約に変換される
- リレーションシップも宣言可能

**セキュリティのコード定義**:
- `@role` デコレーターとポリシー関数で行レベルセキュリティを宣言できる
- 例: 「認証済みユーザーは自分自身の配送記録のみ参照可能」というポリシーをコードで表現

**スキーママイグレーションの自動化**:
- データモデルを変更すると、Rayfinが変更を検知してマイグレーションを自動生成・適用する
- 開発者が手動でマイグレーションスクリプトを管理する必要がない

**コンフィグレーション（YAML）**:
- データベースの dialect を設定（現在は Microsoft SQL Server、将来は PostgreSQL も対応予定）
- ダイアレクト変更はコンフィグの1行を変えるだけで、アプリコードは変更不要

## チャプター3: デモ1 - 配送アプリの構築（3:30頃）

Benが実際のデモを実施。シナリオ: 「Zaba」というホームインプルーブメントストアが新しいホームデリバリーサービスを開始し、配送ドライバー向けアプリ・管理者向け監視アプリが必要になった。

**手順**:
1. VS Code + ターミナルを開き、`rayfin create` コマンドを実行
2. テンプレート選択画面で「blank app」を選択し、プロジェクト名として「Delivery App」を入力
3. プロジェクトがスキャフォールディングされ、フロントエンド・バックエンドの両方に必要なファイルと、Rayfin SDK/CLIの使い方を記述した**エージェント向けインストラクション**が生成される
4. プロジェクトディレクトリに `cd` して `rayfin up` を実行
5. Fabric上にデータベースとアプリが自動プロビジョニングされ、ローカル開発環境がリモートリソースに接続された状態で起動

**エージェントへの指示**: 「Zabaの配送ドライバーが写真と商品状態をログできる配送アプリを作って。顧客が受取確認にサインできるようにしてほしい」とプロンプトを入力し、エージェントがアプリ開発を完了（デモでは「ビルドデモマジック」として完成済みの状態に飛ばした）。

**デモ結果確認**:
- 完成したアプリがFabricポータル上で動作しており、ドライバーがタブレットで顧客にサイン確認をもらえるUIが実現
- Fabricのワークスペースに「Delivery App」アーティファクトと子SQLデータベースが作成されていることを確認
- SQLデータベースを開くと、デモで確認した配送記録がリアルタイムで書き込まれていることを実証
- FabricのChrome（ポータルUI）外で独立したURLを持つアプリとしても公開可能

## チャプター4: Rayfinの内部アーキテクチャ詳解（8:15頃）

Sachinがコードレベルで詳細説明。

**コネクター機能（Fabric OneLake上の既存データへの接続）**:
- 新規データだけでなく、OneLakeにある既存データ（データベース・ウェアハウス・セマンティックモデルなど）にも接続できる
- データソースをYAMLコンフィグに宣言するだけで、エージェント向けインストラクションが自動的にテーブルスキーマを読み取りTypeScriptクラスを生成してくれるため、型安全にデータを操作できる
- セマンティックモデルに数百テーブルある場合でも、必要なテーブルだけを指定してスキーマを取り込める
- 書き込みバック（write-back）もデータソースの種類に応じてサポート

**関数（Fabric Function）**:
- 通知送信・外部サービス連携などのサーバーサイドロジックをTypeScriptで記述し、アプリから透過的に呼び出せる
- デプロイ時（`rayfin up`）に該当コードブロックが **Fabric Function** としてデプロイされ、セキュアなサンドボックス内で実行される
- ブラウザ側でなくバックエンドで認証情報を安全に注入できる

**テンプレート機能**:
- 「blank app」「data app」などのテンプレートを用意
- テンプレートには「APIの定義またはMCPサーバーの設定」「エージェントインストラクション」「サンプルコード」「ライブラリ依存関係」が含まれる
- 組織内でテンプレートを共有・標準化できる（例: 全てのダッシュボードを同じデザイン標準で作成）
- テンプレートはGitリポジトリにチェックインしてコミュニティと共有できる

**フロントエンドとバックエンドの関係**:
- デフォルトはフロントエンドもバックエンドもFabric上にデプロイされるが、フロントエンドをAzure上にホストして独自ドメインを付けることも可能
- 複数のフロントエンドアプリが1つのバックエンドを共有できる
- アプリスコープで読み取り専用・読み書き両方などの権限を制御できる
- 現在は認証にFabric認証（Entra ID）が必須だが、将来は匿名認証やGmailなどのソーシャルログイン対応を計画中

Sujataが「Data App Template」（Power BIチームとのパートナーシップで開発）を使った分析アプリ構築を実演。

**背景**: ZabaのCEOが配送アプリに満足し、「顧客が新しい配送体験を気に入っているか確認できるオペレーショナルダッシュボードを作ってほしい」と要求。

**Data App Templateの構成（3コンポーネント）**:

1. **Data Package**: Fabricエンドポイント接続・クエリリトライ・キャッシングなどの基盤を標準化
2. **Visual Package**: ReactとVega-Liteコンポーネントを使ったAI-firstビジュアル。Power BIチームの長年のデータビズ経験をベースにエンタープライズグレードのデフォルト値を提供
3. **Agent Skills**: コーディングエージェントにこれらのパッケージの効果的な使い方を教えるインストラクション。見た目にこだわったアプリを生成できるよう設計

**デモ手順**:
1. Fabricポータルの「新しいアイテム」から「App」アーティファクトタイプを選択（新機能）
2. 「analysis app」と名前を付けて作成
3. テンプレート選択で「Data App Template」を選択
4. テンプレートからプロンプトをコピーし、VS CodeのCopilot（コーディングエージェント）に貼り付けてEnter
5. エージェントがデータアプリのスキャフォールディングを実行
6. 追加要件として「Zabaの配送セマンティックモデルのURLを指定し、顧客満足度を分析したい。問題をプロダクトチームにエスカレーションするフラグボタンも追加したい」とプロンプト
7. エージェントが自動でDAXクエリを含む分析ダッシュボードアプリを構築

**デモ結果**:
- 数プロンプトで完全な分析アプリが完成
- ビジュアルのレイアウト・デザインの詳細指定は不要（エージェントが自動で適切なフォーマットを選択）
- フラグ・エスカレーションボタンが追加され、クリックでプロダクトチームへのメール送信機能も実装
- 「データを見るだけの静的ダッシュボード」ではなく「データを起点に行動を起こせるアプリ」として完成

**特徴**: Rayfinにより、かつては分離していた「アナリティクスチーム」と「アプリ開発チーム」の成果物が統合された。セマンティックモデルへの投資（DAX、データ定義など）をアプリ開発に再利用できるという大きな利点がある。

## チャプター6: なぜMicrosoft Fabricが最適なプラットフォームか（22:00頃）

Sachinがまとめ説明。

**FabricがRayfinアプリの理想的なホスト先である理由**:

1. **エンタープライズセキュリティ・コンプライアンスがデフォルト**: Fabric内の全アーティファクトには組織のセキュリティルールとコンプライアンスが適用済み
2. **OneLake統合**: Fabric上の全アーティファクトデータはOneLake（「データのOneDrive」）に格納。Rayfinアプリのデータも同じOneLake上に乗るため、ビジネスユーザーがデータサイエンスや下流分析に活用できる
3. **統一セキュリティ境界**: アプリデータと分析データが同一のセキュリティ境界内に共存
4. **SaaS型インフラ管理**: FabricはSaaS提供のため、インフラの管理負担が最小限
5. **統一Fabricキャパシティ課金**: 分析ワークロードに使っていたキャパシティをそのままアプリにも割り当て可能

**開発ワークフロー**:
- ユーザーコード（関数・Webアプリ）はローカル開発
- 基盤サービスはFabricのdevワークスペース（推奨）またはローカルDockerコンテナ（実験的機能）の2択
- `rayfin up` でパッケージングし、dev→staging→productionとワークスペース間のプロモーションが可能

**セルフホスト対応の予告**:
- Fabricへのデプロイを必須としない選択肢も提供予定
- Rayfinランタイムの一部をオープンソース化し、コミュニティと共同で開発していく意向を表明

## まとめ

**Rayfin** は、エージェントによるコーディングが普及する時代において、エンタープライズ向けアプリの「安全なバックエンド」という空白を埋めるMicrosoftの新フレームワークである。TypeScript SDKとCLIでデータベース・関数・セキュリティポリシーを宣言的に定義し、`rayfin up` 一発でMicrosoft Fabricへデプロイ。Fabricの持つSaaS型インフラ管理・OneLake統合・エンタープライズセキュリティが即座に適用される点が最大の強みである。

**発表された新機能・サービス（ステータス整理）**:
1. Rayfin SDK + CLI（Public Preview相当、github.com/microsoft/rayfin）
2. Fabricアーティファクトタイプ「App」の追加（Public Preview相当）
3. Data App Template（Power BIチームとの共同開発）
4. FabricポータルからのApp作成UX
5. OneLakeデータコネクター（セマンティックモデル・データベース・ウェアハウス接続）
6. Rayfin Fabric Function統合（近日対応予定）
7. PostgreSQLダイアレクトサポート（ロードマップ）
8. Replit × Rayfin統合（Private Beta）
9. ソーシャルログイン・永続無料ティア（ロードマップ）
