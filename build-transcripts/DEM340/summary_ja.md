## 全体像

本セッションは約26分のデモ中心セッション（DEM形式）で、エンタープライズ向けエージェント構築の2つの柱——**Microsoft Foundry**（エージェントを構築・評価・公開するプラットフォーム）と**Agent 365**（エージェントを観測・ガバナンス・セキュアにする管理基盤）——を、ライブデモを交えて一気通貫で解説した。登壇者のSriはAgent 365担当GPMとして、開発者視点とITアドミン視点の両方を行き来しながらエンドツーエンドのワークフローを実演した。

エンタープライズでAI採用が進まない最大の障壁は「AIが社内システムで何をしているかわからない」という不透明性だと指摘。その解決策として、**Work IQ**（Microsoft 365のメール・Teams・SharePointなどの組織コンテキストをエージェントに供給するAPI/MCPレイヤー）と**Foundry IQ**（AzureストレージをAzure AI Searchで自動インデックス化してRAGとして利用できる知識データベース）を組み合わせ、エージェントに「適切な文脈」を与える仕組みを示した。さらに構築から公開までをFoundry上で完結させ、IT管理者がAgent 365 Admin CenterでAgent IDベースのガバナンスを行う全体像を紹介した。

Work IQは**2026年6月中旬にGA（Generally Available）予定**（セッション時点では「あと2週間」）と明言されており、本セッションはGAに向けた主要機能の事前披露の性格を持つ。Agent 365 SDKは**LangChain・AWS Bedrockなど非Microsoftスタックにも対応**し、特定プラットフォームへのロックインを避けるオープンなガバナンス戦略が強調された。

## チャプター2：Work IQとは何か——概念説明とGA発表（0:02頃）

### Work IQの3要素

Work IQは「データ」「コンテキスト」「スキル・ツール」の3要素から構成される。今回のセッションでは特に**Work IQ MCP**（Model Context Protocol経由でのアクセス）に焦点を当て、他にA2A（Agent-to-Agent）プロトコルおよびREST APIも公開予定であると述べた。

### Work IQ GAタイムライン（新機能発表）

- **Work IQ: GA予定 2026年6月中旬**（セッション開催日から約2週間後）
- GA後は「最適化されたUX」「セキュア」「包括的」の3つの特性を持つエージェントを構築可能になる
- **セキュリティ面の保証**: エージェントは自分がアクセス権を持つSharePointドキュメント・メールのみ参照可能（On-Behalf-Of認証およびエージェントアイデンティティの両方に対応）

### Work IQ MCPの実体

Work IQ MCP経由でエージェントは以下を利用可能：
- メール・Teams・SharePointなどのM365コンテキストの取得
- ツールの呼び出し（ask mode等）
- **エージェント専用のセキュアなワークスペース**（スクラッチパッド）——ランタイム終了時に自動クリアされるため機密データが長期保存されない設計

## チャプター3：Foundry IQとは何か——RAGの自動化（0:07頃）

### Foundry IQの仕組み

Foundry IQは「再利用可能な知識データベース」として機能するコンセプトで、以下の自動化パイプラインが特徴：

1. **Azure Blob Storage**にPDF・RFP・RFQ・営業資料・価格表・製品スペックなどのファイルを保存
2. **Azure AI Search**が自動的にBlobをベクターインデックスに変換
3. エージェントはそのインデックスをFoundry IQとして利用し、セマンティック検索ベースのRAGを実行

開発者はインデックス作成ロジックを自ら実装する必要がなく、「コンテナ作成→ファイル投入→Foundry IQとして接続」の3ステップで知識ベースをエージェントにアタッチできる。

### エンタープライズグレードのセキュリティ

- ストレージコンテナに設定したアクセス権限がFoundry IQにも引き継がれる
- エージェントは自分がアクセスを許可されたドキュメントのみを参照可能

## チャプター4：ライブデモ——エージェント構築と公開（0:04頃〜0:16頃）

本チャプターが本セッションの中核。Azure AI Foundryのポータル上でゼロからエージェントを構築するライブデモを実施した。デモ中に**複数回の待機（ローディング遅延）**が発生し、Sriが「わかってた、こうなるって」とコメントするシーンも見られた。

### デモステップ1：エージェント作成とWork IQの追加

1. Foundryポータルで新規エージェントを作成（名前：**Super Agent 007**）
2. システムプロンプトとして「あなたは007なので、すべてを知っている」と設定
3. **Work IQをツールカタログから検索して追加**——エンドポイント・接続クレデンシャル・テナントIDがすべて自動設定される
4. 保存後、チャットで「Davidからの最後のメールは何？」と質問
5. Work IQ MCPツールが呼び出され、**Human-in-the-loop**が起動：「このツール呼び出しを承認しますか？」と確認を求められた
   - デモ用に「常に許可」を選択してスキップ

### デモステップ2：Foundry IQの接続

6. 「Foundry IQを接続」をクリック→Azure AI Searchサービスの選択画面が表示
7. 事前に準備済みのBlobコンテナ（価格ガイド・バトルカード・製品仕様書が格納）を選択
8. 知識ソースとして接続完了——この1クリックでRAGが有効化
9. 既存の会話履歴から「製品の値引きガイダンスは？」という質問のデモ結果を参照
   - 回答には**引用（citation）**付きで、回答合成がFoundry IQから行われたことを明示
   - Work IQ MCPを使って「Davidへメール返信」まで実行するデモも実施

### デモステップ3：Evalsの設定と実行

10. 「このエージェントは公開準備できているか？」という問いかけ→「テストが必要」と会場からの声
11. Foundryポータルの評価機能で以下を設定：
    - **評価モード**: シングルターンまたはマルチターン
    - **データソース**: 既存会話またはシミュレーションデータのアップロード（JSONまたはCSV形式）
    - **アップロードデータ構造**: プロンプト・テストケース説明・期待する出力・希望ターン数
12. **評価指標（Evaluators）**:
    - Task Completion（タスク完了率）
    - Task Adherence（タスク遵守率）
    - Customer Satisfaction / CSAT
    - **Groundedness（根拠性）**——ナレッジソースに根拠した回答かを検証
    - Coherence（一貫性）
    - Tool Selection Accuracy（ツール選択精度）
    - Tool Output Utilization（ツール出力活用度）
13. 実行済みのevalから表示されたスコア例：**Task Completion 88%、Tool Selection 94%**など

### デモステップ4：Company Storeへの公開

14. eval通過後、「Company Store（社内ストア）」へ公開——テナント内の全従業員が利用可能な中央リポジトリ
15. 公開操作により**以下が自動実行**：
    - Bot Service（Azure Bot Service）が自動作成
    - **Teams チャンネルおよびM365 Copilot チャンネルへの同時公開**
    - **Agent 365 レジストリへの登録**（Agent IDの自動割り当て）
16. 公開完了後「Admin Centerで承認してください」というメッセージが表示

## チャプター5：Agent 365 Admin Centerのデモ——ガバナンスの実践（0:16頃〜0:25頃）

公開後、Sriが「ITアドミン」に役割を切り替えてAgent 365 Admin Centerを操作するデモを行った。途中**画面切り替えのラグによる待機**があり、「Can we show the demo?」と別のスタッフに呼びかける場面も見られた。

### Agent IDの詳細説明

- Agent IDは**2つの重要コンポーネント**を持つ：
  1. **ユニークなプリンシパル**: テナント内のどこにデプロイ・実行されていても同一エージェントを識別できる一意の識別子
  2. **IDと権限**: 人間ユーザーと同様のアイデンティティ・パーミッション管理が可能

### Agent 365 Admin Center の主要機能

1. **スコアカード**: テナント内のAIアーティファクト全体のサマリー
2. **Agents at Risk**: 問題のあるエージェントの警告
3. **アクティブユーザー数**: エージェント利用状況の把握
4. **エージェントレジストリ（マップビュー）**:
   - Copilot Studio製・Foundry製・外部プラットフォーム製（Amazon、Google、Databricks、Salesforce AgentForce）のエージェントを一元管理
   - 外部エージェントはSDK経由で同期してレジストリに取り込み可能
   - **マップビュー**で異なるプラットフォームのエージェント間インタラクションを可視化
5. **承認リクエスト（Requests）**: 新規エージェントが公開されるたびにアドミンが承認・却下を判断

### ローカルエージェントの検出（新機能）

- **GitHub Copilotなどのローカルエージェントを自動検出してレジストリに表示**（Satya Nadella基調講演でも言及）
- Agent 365は、どのデバイスでGitHub Copilotが実行されているかを表示
- **MXC（Microsoft Execution Container）ポリシーの配布**: Intuneと連携し、エージェントをコンテナ隔離環境で実行させるポリシーをデバイスに配信
- アクセス可能なフォルダパスをきめ細かく制御可能

### シャドウエージェントの検出

- **シャドウエージェント**（未申請・非公式に実行されているエージェント）の検出をIntune + Global Secure Access（推測：ZTNA）技術で実現
- Microsoft Defenderがローカルエージェントを実行しているエンドポイントを検出

### ツールガバナンス（Tool Governance）

- エージェント単体だけでなく**MCPサーバー・プラグイン・コネクタなどのツール層もガバナンス対象**
- Work IQ MCPがAdmin Centerのツール一覧に表示され、テナント全体で許可/禁止の制御が可能
- **OPAのRegoポリシー**を設定することで、ツール利用の詳細ルールを定義
- **Bring Your Own MCP Server対応**: Agent 365 SDKを使って自社MCPサーバーを公開すると、Admin CenterでITアドミンが承認/却下できる仕組み

## チャプター6：Agent 365の戦略的位置づけとセキュリティ統合（0:18頃〜0:25頃）

### 52ポイントのガバナンスギャップ問題

スライドで提示された数字：**現在本番稼働中のエージェント数とエンタープライズグレードに成熟したエージェント数の間に52ポイントの乖離**がある。多くのエージェントがITアドミンの把握なしに不適切な行動を取っているという現実を指摘。

### Agent 365が解決する3つの柱

1. **Observe（観測）**: テナント内エージェント活動の可視化
2. **Govern（統制）**: ポリシーによるエージェント行動の制御
3. **Secure（保護）**: セキュリティ脅威からの防御

### Microsoft Defender との統合

- Agent 365 SDKを使ってビルドされたエージェントは**ツールゲートウェイ**を経由し、そこにDefenderが深く統合されている
- 防御対象：
  - **データ漏洩防止（ASCII Smuggling等によるデータ外部流出の防止）**（推測：自動字幕「esky smuggling」はASCII Smugglingを指す）
  - **リアルタイムのプロンプトインジェクション対策**
  - **悪意あるサイトへのアクセスブロック**
  - **フィッシング・不審なメールへの返信ブロック**

### Microsoft Purview（感度ラベル）との連携

- 「高度に機密」などのデータ感度ラベルをエージェントが尊重する仕組みを提供
- ラベルが付与されたデータをエージェントが外部に送信しようとするとブロック

### Intune・Microsoft Security製品との統合

Agent 365は以下の製品を組み合わせた統合プラットフォーム：
- **Microsoft Intune**: MXCコンテナポリシー配布、デバイスサンドボックス化
- **Microsoft Defender**: エンドポイント検出、プロンプトインジェクション保護
- **Microsoft Purview**: 感度ラベルの尊重、データ損失防止

### マルチクラウド・マルチフレームワーク対応（重要な差別化ポイント）

- **Agent 365 SDKは特定のMicrosoftスタックに縛られない**
- LangChainで構築したエージェントにもAgent 365 SDKでインストルメンテーションを追加すれば、Microsoftの観測・ガバナンス・セキュリティ機能をそのまま利用可能
- AWS Bedrockで構築したエージェントも同様
- GitHub Copilot、Claude Code（推測：自動字幕「cloud code, open claw」はClaude Codeを指す）なども検出・ガバナンス対象
