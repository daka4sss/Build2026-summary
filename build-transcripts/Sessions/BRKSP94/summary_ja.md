## 全体像

本セッションは NVIDIA と Microsoft の共同セッションであり、NVIDIA Nemotron モデルファミリーの最新モデル「Nemotron 3 Ultra」の発表と、それを Microsoft Foundry Hosted Agents 上で動かすためのアーキテクチャ・デモを中心に構成されている。

「ChatGPT モーメント」から DeepSeek によるオープン推論モデルの登場、さらにエージェント時代への進化という約3〜4年間の技術的変遷を振り返りながら、エンタープライズ向けエージェント活用に必要な要件（モデルの系統化、スペシャライゼーション、コスト効率）を提示する。

セッションのゴールは、NVIDIA の最新フロンティアモデルを単なるベンチマーク数値としてではなく、「実際のビジネスシナリオで動くエージェント」として見せること。Hermes Agent ハーネスと Nemotron 3 Super/Ultra を組み合わせ、Microsoft Foundry の Hosted Agents / Toolbox / Entra ID 統合を通じてエンタープライズグレードのエージェント基盤を構築するデモを実演した。

## チャプター 2: エージェントアーキテクチャの概観（2:00頃）

Joey はエージェントの構造を図解しながら説明した。

- **プロンプト（左上）**: ユーザーからのリクエスト・ジョブ。
- **エージェントループ（中央）**: コンテキスト/バックグラウンド知識を持ち、「観察→計画→推論→行動」のループを繰り返してタスクを完遂する。
- **ツール・スキル（右上）**: CPU/GPU 上で動作。CUDA ソフトウェアスタックも活用。
- **セキュリティ・ガバナンス（右）**: ネットワークプロトコルやコンテンツアクセス制御。
- **メモリ（下）**: ネットワーク上・ローカル・CPU/GPU・LLM 内部にまたがる短期・長期メモリ。
- **オーケストレーション（左）**: 1つのエージェントが他のエージェントと協調し、フリートを横断してワークロードをオーケストレーションする。

エージェントは**システム・オブ・モデルズ**の概念で動く、というのが NVIDIA の基本的なスタンス。企業では単一のモデルではなく、異なる言語・モダリティ・サイズ・場所で動く複数のモデルが連携することになると説く。

## チャプター 3: NVIDIA Nemotron ファミリーの概要（5:46頃）

Nemotron はモデル（チェックポイント）・データ・ツールを包含する**ファミリー**として定義される。

### 主要ケイパビリティ

| 領域 | 概要 |
|------|------|
| Reasoning（推論） | 最も注目されるフラグシップ機能 |
| Vision | 視覚理解 |
| Information Retrieval | Embedding・Re-ranking |
| Safety | コンテンツモデレーション |
| Speech | Speech-to-Text / Text-to-Speech |

### 3サイズ展開

- **Nemotron Nano**（2024年12月発表）: 小型データセンター GPU 向け。Hybrid MoE 構成、Total 30B / Active 3B。
- **Nemotron Super**（2025年3月発表）: H100 1〜2枚程度の構成。
- **Nemotron Ultra**（本セッション時点で「今週火曜日に公開」として発表）: 最大・最高性能。2×B200 クラスの大型データセンター向け。550B / Active 55B。

すべてのモデルには**オープンデータセット**（事前学習・後学習データ、RL 環境）、**NeMo Gym によるスキル**、および**研究論文**が公開される方針。

## チャプター 4: Nemotron 3 Ultra の発表と技術的ブレークスルー（7:52頃）

**Nemotron 3 Ultra** は本セッション直前の日曜日（GTC 2026 CEO Keynote）で発表された NVIDIA 史上最大・最高性能のオープンモデルであり、本セッションで詳細が共有された。

### 3つの技術的ブレークスルー

1. **マルチティーチャー On-Policy 蒸留（Multi-Teacher On-Policy Distillation）**
   - SFT→RL という従来の流れから進化。特定タスクに特化した複数の「Ultra ティーチャーモデル」から知識を蒸留し、Nemotron 3 Ultra に統合。幅広いスキル習得を実現。

2. **NVFP4 精度フォーマット（Blackwell 最適化）**
   - Blackwell アーキテクチャに最適化した新精度フォーマット NVFP4 を採用。メモリ削減と計算高速化を両立。
   - **特筆点**: 初めて**単一チェックポイントファイル**で Blackwell（NVFP4）と Hopper（FP8 fallback）の両方で動作するよう設計。Hugging Face からのダウンロードや選択が非常にシンプルになった。

3. **オープンエコシステムハーネス対応**
   - OpenCode / Hermes Agent / Open Claude / PyTorch など主要なオープンハーネスでの動作検証を実施。エコシステムでの相互運用性を重視。

### アーキテクチャ特徴

- **Hybrid MoE アーキテクチャ**: コンピュート効率・メモリ効率を最適化。
- **Latent MoE アーキテクチャ**: 少ないコンピュートでより多くの専門家（エキスパート）に到達可能。
- **Multi-Token Prediction（MTP）**: 1回の推論クエリで複数トークンを予測し、スループット向上。
- **100万トークンコンテキスト長**: アジェンティックタスクの長期メモリとして活用可能。

## チャプター 5: ベンチマーク・コスト効率評価（13:16頃）

Joey はベンチマーク評価に**2種類の視点**を示した。

### 従来型ベンチマーク（タスク精度）

サードパーティ「Artificial Analysis」が計測する以下の指標でオープンモデルとの比較を実施:

- **Bench Bench**: エージェントの生産性（正しいツール呼び出し、タスク完遂、効率性）
- **Enterprise OPS Gym**（ServiceNow提供）: パスワードリセット等の長期プランニングが必要なエンタープライズシナリオ
- **Coding**: コーディング精度
- **Instruction Following**: 指示厳守
- **Knowledge Work**: 製造・医療などの業界ドメイン知識（PhD/MBA レベル）

Nemotron 3 Ultra は、GLM 51・Kimi K2.6・Qwen 3.5 等の競合オープンモデルを上回るスコアを示し、**フロンティアレベルの精度**を達成した。Nemotron 3 Super（3月リリース）比で約5倍の推論速度も達成。

### 新コスト効率フロンティアチャート（GTC 2026 CEO Keynote でも初公開）

「精度 vs タスク完遂コスト」という新しい視点のグラフを提示:

- **Y軸**: タスク正解率（Coding エージェントタスクの正答率）
- **X軸**: タスク完遂コスト（CoreWeave・Deep Infra の最低単価を使用してトークン数×時間でコスト算出）

Pareto 曲線上で Nemotron 3 Ultra は**左上（高精度・低コスト）**に位置しており、フロンティアインテリジェンスを低コストで実現する方向への進化を示した。

## チャプター 6: デモ動画 — Hermes Agent + Nemotron による製品ローンチシナリオ（15:46頃）

Joey がデモ動画を再生し、解説を加えた（一時停止して補足する場面もあった）。

### シナリオ概要

- 小規模企業が2週間以内に製品ローンチを実施。
- 4名のシニアリードがそれぞれ異なる職能（マーケティング・エンジニアリング等）で従事。
- 各ワークフローに **Hermes Agent on Nemotron 3 Ultra** が並走し、推論・文書作成・判断を支援。

### 示された仕組み

- 個人が Hermes を修正・フィードバックすると、そのフィードバックは**再利用可能なスキル**として保存される。
- **Hermes Curator**（Nemotron 3 Super で動作）がスキルをマージ・重複排除・書き換え・テストし、共有可能な状態に仕上げる。
- 企業レビュー・承認を経たスキルは**Hermes Collective Wisdom**（社内証明済みメソッドライブラリ）に追加。
- 「メソッド（やり方）」は共有されるが、ローンチデータ（機密情報）はプライベートに保持。
- 数ヶ月後には、同僚1人の改善が全員のワークフローを底上げする仕組み。

Joey はデモ後に「将来の転職活動では、会社がどんなエージェントやスキルを持っているかを聞くようになるかもしれない」と将来像を語った。

## チャプター 7: ライブデモ — Foundry Hosted Agents + Hermes + Nemotron（19:06頃）

Steven McCullough（NVIDIA AI Solutions Architect）に交代し、実際の Foundry 環境でライブデモが実施された。

### Foundry Hosted Agents の主要機能

- **Bring Your Own Container**: 独自のコンテナ・ハーネス・環境を Foundry にデプロイ可能。
- **エージェント ID（Microsoft Entra ID 連携）**: 人間の同僚と同等のアイデンティティをエージェントに付与し、組織全体で管理。
- **Isolated Session**: 生成されたコードやドキュメントはセッション単位で隔離。
- **ライフサイクル管理・コンプライアンス**: 監査要件・バージョン管理の充足。

### デモの流れ

**ステップ1: エージェント確認**

Foundry Agent Service 上で新セッションを開始し、「どのエージェント・モデルで動いているか」を質問。Nemotron 3 Super 上の Hermes Agent であることを確認。

**ステップ2: E メールからのタスク委譲**

同僚 Alex から受け取ったメール（LLM Perf Bench への chat completions エンドポイント追加要求）を、エージェントに口頭で委譲。

- **ポイント**: メール本文をプロンプトにコピーせず、「Alex からメールが来た。対応して」という自然言語指示のみ。
- エージェントは Outlook 経由でメールを検索 → GitHub のリポジトリを解析 → コーディングサンドボックスでコード生成・テスト → PR を自動作成。

**ステップ3: Foundry Toolbox による統合管理**

Outlook・GitHub・コーディングサンドボックスの各サービスを**単一の Foundry Managed Toolbox** で一元管理。

- Foundry カタログには MongoDB・Teams・Cosmos DB 等の MCP サーバーが組み込み済み。カスタム MCP サーバーも追加可能。
- ツールごとに read/write 権限を細かく設定可能（例: Teams は読み取り専用、メール送信は不可）。

**ステップ4: PR のフィードバック → スキル学習**

Steven が2点のフィードバックを入力:
1. オリジナルリクエスト者の Alex をレビュワーに追加すること
2. 関数に docstring を含めること

さらに「**このフィードバックを将来も記憶してほしい**」と指示。エージェントは PR を更新し、Hermes 内部の `skill_manage` 関数を呼び出してスキルとして永続化（Foundry のトレース画面で確認可能）。

**ステップ5: Microsoft Teams 経由での継続確認**

Foundry Agent Service から Teams にエージェントをパブリッシュ。Teams の UI から同エージェントに接続し、別セッションであるにもかかわらず、直前に作成したスキル（LLM Perf Bench リポジトリ向けルール）を正しく記憶していることを確認。

**特筆事項**:

- OAuth パススルーにより、エージェントがユーザーのアイデンティティを継承して GitHub にコミット。コミット履歴はユーザー本人のものとして記録される。
- Foundry のトレース機能により、どの MCP サーバー・ツールを使ったか、どのステップを踏んだかをステップごとに監査可能。

## チャプター 8: アーキテクチャまとめと Entra ID ガバナンス（30:21頃）

Steven が Foundry の統合価値を整理した。

### 3層の価値提供

| レイヤー | 役割 |
|----------|------|
| **Nemotron** | 最高トークン効率、フロンティアインテリジェンス、オープンモデル＋トレーニングデータ、エージェントタスク向け後学習 |
| **Hermes Agent** | マルチモデルオーケストレーション、継続的スキル学習、組織横断での知識蓄積 |
| **Microsoft Foundry** | 実行インフラ、Entra ID によるエージェントID管理、Toolbox（MCP 一元管理）、セキュアセッション管理、M365 統合 |

### Microsoft Entra ID によるエージェントガバナンス

Azure ストレージアカウントの IAM 設定からエージェントの Entra ID を検索し、ロールを付与する手順をライブデモで示した。アクセス付与・剥奪・監査がすべて人間の同僚と同じフローで実施可能。Azure リソースに限らず M365 エコシステム全体に拡張可能。

### Foundry Toolbox（ツール一元管理）

個別サービスごとに認証フロー・MCP エンドポイント・権限モデルを別々に設定する代わりに、Foundry Toolbox 経由で全サービスを一元接続・制御。エージェントが複雑化するほど、単一コントロールプレーンの価値が増す。
