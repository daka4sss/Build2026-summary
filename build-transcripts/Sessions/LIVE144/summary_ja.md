Scott Hanselman は、OpenClaw のオープンソースプロジェクト作者 Peter について「一夜にして成功したと思われているが、実際には450以上のユーティリティを事前に公開しており、オープンソース界では周知の人物だった」と紹介した。OpenClaw が2025年11月にリリースされた際、Scott はすぐにその可能性に気づき、「彼は Mac で開発しているが、自分は Windows を使っているから Windows 版を作ろう」と考えてコンパニオンアプリを実装した。

## チャプター 3: Windows Companion App の設計方針とコーペティション観（1:43頃）

Scott が Windows 版コンパニオンアプリ（OpenClaw Windows Companion App）を構築するにあたって設定した初期ゴールは「Mac 版とのパリティ（1対1同等）」だった。その上で Windows ならではの差別化として次の問いを立てた。

- アプリパッケージングをどうするか
- パーミッション管理をどうするか
- サンドボックス化の方法をどう変えるか

Scott はこれを「コンペティションではなくコーペティション（coopetition）」と定義した。「OpenClaw がどこでも優れていてほしい。ただ Windows 上では少し上乗せしたい」というスタンスで、Mac 版との「親指相撲（thumb war）」が双方の水準を上げると述べた。MXC（コンテナ関連技術と推測）を立ち上げ済みとして紹介し、今後もさらなる機能追加を予定していると語った。キーノートの後にも Peter が「クレイジーなマッドサイエンティスト的アイデア」を持ち出し、チームが早速実装に走ったエピソードを共有した。

## チャプター 4: コンテナとコンテインメントの違い——エージェント向けセキュリティ基盤（7:53頃）

Scott はキーノートで使った「containers and containment（コンテナとコンテインメント）」という表現について詳しく解説した。これが本セッションの技術的核心部分である。

**コンテナ（Container）= 実装上の概念**
- OCI コンテナ（Docker が代名詞化しているが Docker は一企業）
- WSLC（WSL Container Runtime）を Windows 向けにリリース済み。WSL のもとで Linux コンテナを Windows 上でネイティブ動作させる機能。これにより **Windows でのコンテナ動作がアウトオブザボックスでサポートされた**（発表済み）
- podman など他のコンテナランタイムも選択肢

**コンテインメント（Containment）= 概念・原則**
- 「仕事の周囲に点線を引き、それが漏れ出ないようにする」汎用的なアプローチ
- 実装技術はプロセスコンテインメント、セッションコンテインメント、マイクロ VM コンテインメント、フル VM コンテインメントなど多様
- 例として「WorkIQ から情報を取得するエージェントが、Google Calendar にアクセスしたり、テキストファイルを勝手に書いたりすべきではない」という最小権限原則を示した

Scott は「リーダーシップや管理職は三段階のスライダーバーがあると思いがちだが、実際にはクリックストップが無数にある」と表現し、細粒度のコンテインメント設計が今後の方向性だと述べた。

## チャプター 5: Git ワークツリーによる並列エージェント開発（10:40頃）

Scott が「開発者のワークフロー変革として最も効いた小さな変化」として挙げたのが **Git ワークツリー（git worktrees）** の活用である。

従来のブランチ管理では、1つのフォルダでブランチを切り替えながら作業するのが一般的だった。ワークツリーを使うと、ブランチごとに独立したフォルダを持つことができる。これにより：

- **3〜5個のエージェントを並列実行**できる（OpenClaw コミュニティでは数十並列を行う例もある）
- ブランチ切り替えなしに複数タスクを同時進行できる
- Dev Drive との組み合わせでパフォーマンスも向上する

Scott は「**Windows マシン + Dev Drive + ワークツリー**の組み合わせが非常に良いワークフローを生む」と述べ、**GitHub Copilot アプリにはワークツリーサポートが組み込まれており**、プレビューを抜け出す段階でユーザーがその効果を実感できるようになると予告した（Public Preview からの GA 移行を示唆、推測）。

## チャプター 6: エージェントの未来——動的ポリシーエンジンと IT 管理（11:46頃）

Monica が「エージェントが機械学習を通じて自律的に動くトレンドについてどう見るか」と問うと、Scott は未来のエージェント管理の核心として **動的ポリシーエンジン（dynamic policy engine）** を提示した。

現状の課題意識：
- エージェントは「まさに必要なことだけを行い、それ以上はしない」べきだが、現在は難しい
- 「1ポリシーがすべてに適合する（one policy fits all）」設計では不十分

Scott が描く将来像：
- **ツールコール単位・インテント単位でコンテインメントが動的に生成される**
- スライダーバーの設定値がツールコールごとに自動変化する
- **IT 管理者がポリシーを完全に制御しながら、ユーザーには透明（invisible）に機能する**
- コンテナが機能していれば、ユーザーはそれがコンテナ内で動いていることすら気づかない

これにより「開発者・エンドユーザー・IT 管理者の全員がメリットを得る」三方よしのアーキテクチャが実現するという展望を述べた。

## まとめ

### セッション全体の結論

本セッションは、オープンソースの OpenClaw プロジェクト（Peter 作の高速成長コーディングエージェント）が Microsoft Build 2026 キーノートで Windows 上で動作するデモに至るまでの経緯と、その背後にある Windows プラットフォームの技術的取り組みを明かした対談である。Scott Hanselman が個人として Windows Companion App を構築したことが出発点となり、Microsoft と OpenClaw コミュニティの協働が生まれた。

### 発表された新機能・取り組み（ステータス）

| 機能・取り組み | 内容 | ステータス |
|---|---|---|
| **WSLC（WSL Container Runtime）** | Windows 上で Linux コンテナを WSL 経由でネイティブ動作。アウトオブザボックス対応 | 発表済み（GA相当として言及） |
| **MXC** | コンテナのスペクトラム対応技術（詳細は字幕上不明確、推測：Windows コンテナ関連の新技術名） | 立ち上げ済み、継続改善中 |
| **OpenClaw Windows Companion App** | OpenClaw を Windows で動かすためのコンパニオンアプリ。Dev Drive・ワークツリー統合 | キーノートデモで披露済み |
| **GitHub Copilot アプリのワークツリーサポート** | git worktrees を統合し、並列エージェント実行を可能にする | Public Preview 段階（GA 移行を予告、推測） |
| **動的ポリシーエンジン** | ツールコール単位でコンテインメントを動的生成、IT 完全制御・ユーザー透明 | 将来の方向性として言及（未リリース） |

### 技術者向けの次アクション

1. **git worktrees を今すぐ試す** — `git worktree add` コマンドでブランチごとに独立フォルダを作成し、複数エージェントを並列実行するワークフローを構築する。
2. **WSLC を確認する** — Windows 上でコンテナをネイティブ動作させる WSLC のドキュメントを確認し、エージェントのサンドボックス実行環境として評価する。
3. **Dev Drive を導入する** — Windows の Dev Drive 機能を使い、ワークツリーとの組み合わせによる開発速度向上を検証する。
4. **OpenClaw Windows Companion App の動向を追う** — Peter らのコミュニティ（GitHub 上のオープンソースリポジトリ）をフォローし、Windows 特有機能の追加状況を確認する。
5. **コンテインメント設計を意識したエージェント開発** — 最小権限原則（least privilege）に基づき、エージェントのツールアクセス範囲を明示的に定義するアーキテクチャを採用する。
