## 全体像

本セッションは、エンタープライズ向けエージェント開発における最大の課題「コンテキスト不足」を解決するための、Microsoft の新しいインテリジェンス基盤「Microsoft IQ」を紹介することを目的としている。Amanda Silver と Marco Casalaina の 2 名が登壇し、設計思想の解説と live デモを交互に進める形式で約 44 分間にわたって展開された。

セッションのコア・メッセージは「エージェントが失敗する原因はモデルの能力不足ではなく、コンテキスト不足である」という点だ。登壇者は、アジェンティック AI プロジェクトの 40%以上が失敗すると見込まれる背景として、データソースの断片化・カスタム検索システムの乱立・パーミッションモデルの複雑さを挙げた。その解決策として提示されたのが、4 つのコンテキスト源を統合する「Microsoft IQ」プラットフォームである。

デモは「仮想の配送会社における返金処理エージェント」を題材に行われた。Amanda がメールで送った「返金処理を自動化したい」というアイデアを出発点に、Marco がエージェントを実装する様子を実演。セッション序盤からネットワーク障害が発生し、Marco が終始接続復旧を試みながら解説を続けるというハプニングが連続したが、最終的には VPN（GlobalProtect）を無効にすることで接続が回復し、主要デモを完了させた。

## 1. 問題提起：なぜエージェントは失敗するのか（0:00頃）

Amanda Silver は冒頭で、「ソフトウェアは人が操作するアプリケーションから、インテントで定義され、アウトカムで評価されるエージェントへと進化している」と述べた。これはここ数十年の「自動化の未来」が実現しつつある瞬間だと強調した。

しかし、その実現には大きな障壁がある。**40%以上のアジェンティック AI プロジェクトが失敗すると予測**されており、その原因はモデルの能力不足ではなく、エージェントが必要なコンテキストを持てていないことにある。開発者は現状、断片化されたデータソース・カスタム検索システム・パーミッションモデル・オーケストレーションロジックを手作業でつなぎ合わせなければならず、結果としてエージェントは以下の問題を抱えている：

- ハルシネーションを起こす
- ポリシー境界を侵害する
- 本番環境で壊れる

Amanda の核心的な比喩：「新入社員と経験豊富なベテランの違いのようなもの。ベテランが持つ文脈（ナレッジ）をすべての新規エージェントに最初から与えるにはどうすればよいか」というのがこのセッションの問いかけだ。

## 2. Microsoft IQ の設計思想とアーキテクチャ（2:43頃）

この問いへの答えとして提示されたのが **Microsoft IQ**（コンテキスト層 / アジェンティック Web のためのインテリジェンス基盤）。4 つのコンテキストソースを統合する：

| IQ 名 | カバー領域 |
|--------|-----------|
| **Work IQ** | 組織コンテキスト（M365のメール・Teams・ドキュメント・ワークフロー） |
| **Fabric IQ** | ビジネスデータ（リアルタイムの業務メトリクス・セマンティックモデル・オントロジー） |
| **Foundry IQ** | エンタープライズ知識とポリシー（社内文書・カスタムアプリ・セキュリティ統制） |
| **Web IQ** | ワールドナレッジ（Web・ニュース・画像・動画のリアルタイム情報） |

この 4 IQ が統合されることで、エージェントは「ビジネスの周囲にある人・データ・ワークフロー・ポリシーを共通理解したうえで動作できる」ようになる。効果は 3 点：精度向上・アクションの信頼性向上・エンジニアリングコスト削減（エージェントごとにコンテキストを再定義する必要がなくなる）。

## 4. Web IQ の詳細解説（6:24頃）

Amanda が Web IQ について解説。「エージェントは社内だけでなく、ビジネスが動いているリアルワールドも理解する必要がある」として、消費財配達企業がマイクロイベント（地域の祭典等）を把握してマイクロターゲティングに活用する例を紹介した。

**Web IQ の特徴（3 点）**：

1. **品質（Quality）**：Web・ニュース・画像・動画にまたがるストラクチャード・マルチモーダルインデックス。引用付きで検証可能な回答をエージェントが生成できる。
2. **スピード（Speed）**：P95 で **サブ 200 ミリ秒** のグラウンディングを実現。マルチステップのエージェントワークフローでもレイテンシを抑制。
3. **効率性（Efficiency）**：パッセージレベルのランキングで高シグナル情報のみをサーフェスし、ノイズをフィルタリング。トークン消費量の削減とコスト最適化に寄与。

従来の検索 API と異なり、「モダンなアジェンティックシステムのために設計されたグラウンディングプラットフォーム」と位置づけられている。フロンティアモデルプロバイダーや多くの企業がすでに利用中で、「Azure の一部のお客様に現在提供中」との言及あり。

**採用事例：NASDAQ Board Vantage**  
取締役会・経営幹部向けのリアルタイム意思決定支援ツールに Web IQ を採用。企業内部情報と外部 Web シグナルを、セキュリティ境界を侵さずに組み合わせて提供。速度・品質・シンプルなアーキテクチャによる AI アプリ構築が実現。

Marco は Web IQ デモとして Sandy Fire（セッション会場サンフランシスコから 400 マイル南のシミバレーで実際に燃えている山火事）の情報をリアルタイムで取得しようとしたが、この時点でもネットワーク障害が継続し実演できなかった。

## 5. Foundry IQ の詳細解説（9:38頃）

Amanda が Foundry IQ を解説。「Web IQ が世界の知識をつなぐとすれば、Foundry IQ は企業独自の知識をつなぐ」と定義した。

**Foundry IQ のレイヤー構造**：

- **底層（知識ソース）**：企業データ・ドキュメント・アプリケーション・ライブ Web
- **中間層（コンテキスト層）**：メモリ・エンベディング・セマンティックモデルが情報を「理解」へ変換
- **上位層（エージェント/アプリ）**：ユーザーが対話するエージェントやアプリケーション

設計原則は「委譲（delegation）」。各レイヤーが単一の責務を担い、開発者はエージェントごとに検索インフラを再構築しなくてよい。定義したナレッジベースを複数のエージェントで共有・再利用できる。

**主要機能**：
- 自動インジェスト・エンリッチ・接続による統合ナレッジレイヤー
- 実行時に必要な情報を適切なソースから自動取得（アジェンティック検索 = sub-agent が再試行・再ランキングを担当）
- セキュリティ・ガバナンス・ポリシー施行がプラットフォームに組み込み済み（後付けでなく設計に内包）

**新機能発表**：  
**Foundry IQ サーバーレス開発者ティア**を新たに導入。すべての開発者がすぐに Foundry IQ でビルドを開始できる入口を提供し、本番準備が整ったらスケールアップできる設計。（GA/Preview ステータスは明示なし）

Marco が Foundry IQ の画面を見せた際に「35 エージェントのうち 31 が稼働中」という状況を示し、「同じデータソースに複数エージェントを接続できる再利用性」がこの製品の核心的価値と説明した。

**採用事例：Sitecore**  
デジタルエクスペリエンス・コンテンツ管理のリーダー企業。再利用可能なナレッジベース・アジェンティック検索・エンタープライズグレードのセキュリティをそのまま活用し、マーケティング・ブランドナレッジを全エージェントが適切なパーミッションで利用できるよう構築。

## 6. Fabric IQ の詳細解説とオントロジーデモ（16:21頃）

Amanda から Marco にバトンが渡り、**Fabric IQ** の解説とデモに移行。

**Fabric IQ の役割**：「Foundry IQ が組織が"知っていること"を解放するとすれば、Fabric IQ は組織で"今何が起きているか"をエージェントに理解させる」。リアルタイムの業務メトリクス・構造化ビジネスデータへのエージェントアクセスを担う。

**アーキテクチャ（3 層）**：

| 層 | 概要 |
|----|------|
| **1 Lake（ワンレイク）** | アナリティカル/オペレーショナルデータの統合データ層。マルチクラウド・異種システムのデータを移動・複製なしで統合。すべてのチーム・アプリ・エージェントが単一の「真実の源泉」から動く |
| **セマンティックモデル** | Power BI で定義済みのメトリクス・概念をそのまま引き継ぎ。エージェントが「役員報告と同じ数字」で推論できるようにする |
| **オントロジー** | ビジネスエンティティ（顧客・注文等）・関係性（「顧客がパッケージを送る/受け取る」という動詞）・ルール・プロセスを定義。テーブルスキーマではなく概念レベルで推論可能にする |

**デモ：オントロジー生成（22:16頃）**

ネットワーク障害で「Generate ontology」ボタンを押しても反応なし（笑いを取りながら Marco が自ら「全部 UI に loading も出ない」と実況）。事前に生成済みのオントロジー（パッケージ・顧客・ドライバーの関係グラフ）を表示した。

オントロジーとセマンティックモデルの違いを Marco が説明：セマンティックモデルはテーブル間の関係を定義するが、オントロジーは「package = 箱・ケース・シップメントというシノニムを持つビジネスエンティティ」という概念レベルの定義を持つ。

**重要コンセプト：コンテキスト委譲（Context Delegation）**

モデルのコンテキストウィンドウには上限があり、レイクハウスを直接クエリさせるには大量のコンテキスト（データ辞書・スキーマ・サンプルクエリ・補足指示）が必要になる。これを解決するのが **Fabric データエージェント（Fabric Data Agent）**：

- オントロジー・レイクハウス・その他データソースに接続した専用サブエージェント
- 業界特有の社内用語（例：SRC = Shipping Refund Concession）を事前定義
- ダウンストリームエージェントは「Fabric データエージェントに問い合わせる（phones a friend）」だけでコンテキストを取得
- **MCP サーバーとしてオントロジーを直接公開**することも可能
- Foundry IQ から Fabric オントロジーに接続する経路も提供（内部は MCP サーバー）

**採用事例：Qcells（Quanta Q Cells / 推測）**  
AI データセンター向けエネルギー管理。人間だけでは推論しきれないほど動的・複雑な問題を、Fabric IQ 構築の運用モデルで解決。人間オペレーターの制御権を維持しつつ、エージェントが推奨アクションを継続的に最適化。

## 7. Work IQ 詳細解説とエージェントアイデンティティデモ（27:13頃）

Marco がネットワーク復旧を試みる間、Amanda が Work IQ を詳しく解説した。

**Work IQ の定義**：M365 上で組織が蓄積してきた知識（メール・Teams チャット・SharePoint・ドキュメント・ワークフロー）をエージェントに与えるための「Microsoft IQ の人レイヤー」。

**従来の Microsoft Graph 等との差別化（3 点）**：
1. **エージェントファースト**：人間スケールのAPI設計でなく、エージェントの処理速度・パターンに合わせた設計
2. **生データではなく組織コンテキスト**：エージェントが組織理解に基づいて推論できる形式
3. **既存セキュリティモデルの上に構築**：M365 テナントのセキュリティが複製されることなくそのまま活用。Work IQ データは M365 テナントコンテキスト内に留まる

**4 つの機能**：
- **Chat**：エージェントが人・他エージェントと対話。Microsoft Copilot でのエージェント間コラボレーション
- **Text（コンテンツグラウンディング）**：メール・会議・Teams チャット・ドキュメントから組織状況を把握。開発者が独自の取得パイプラインやインデックスを構築する必要なし
- **Tools（アクション）**：M365 操作（メール送信・Teams 投稿等）をガバナンス付きで実行
- **Workspaces**：エージェントの中間成果物を永続保存。長時間タスク・複数エージェント/人との協調作業に対応

**Miro との連携事例**：コラボレーションツール Miro が Work IQ と統合し、M365 コンテキスト（ドキュメント・会話・関係者・意思決定履歴）を Miro キャンバスから直接アクセス可能に。コピー&ペーストや古いスナップショットへの依存をなくし、リアルタイムの M365 コンテキストを Miro 上で直接利用できる。

**ネットワーク復旧（33:15頃）**：観客の中から「GlobalProtect（VPN）をオフにしてみて」と助言してくれた人物のおかげで接続が回復。Marco は「ステージで経験した中で最大の技術的惨事だったが、天国かヴァルハラから来てくれたありがとう」とコメント。

復旧後のデモでは以下を実演：

1. **Foundry から M365 への統合**：Foundry で定義したエージェント（返金処理エージェント）が「M365 ブループリント（blueprint）」→「エージェントテンプレート（agent template）」へ変換される
2. **エージェントインスタンス化と組織図登録**：Teams からテンプレートをインスタンス化すると、エージェントは独自の**アイデンティティ**を持ち、**組織図（org chart）に登録**される。返金処理エージェントは Marco 配下に表示
3. **専用メールボックス・Teams チャット**：エージェントは独自の Teams ボックスとインボックスを持つ
4. **実際のメール処理**：Marco が Maria Garcia さんの「荷物が届かない」メールを返金処理エージェントに転送。エージェントは Work IQ 経由でメール読み取り→状況確認→Maria に返信（Marco を CC）を完遂（デモでは荷物情報が見つからず謝罪メールが送信された）

**Work IQ のセキュリティモデル**：
- Copilot CLI 経由では「ユーザーとしてログイン」し、ユーザーの全権限を継承
- エージェントインスタンスには**独立したパーミッションスペース**（例：「メール送受信OK・Word 編集NG」など最小権限の原則を実現）

Work IQ を Marco は「Microsoft アプリ（Outlook・Teams・SharePoint・Word）のエージェント向けヘッドレスバージョン」と表現した。

## 8. クロージングとガバナンスの重要性（39:49頃）

Amanda がデモ総括とセッションのクロージングを担当。

**ガバナンス基盤**：Microsoft IQ の各レイヤーはすべて「アイデンティティ・ガバナンス・セキュリティ」という同一基盤の上に構築されている。
- エージェントはデフォルトでパーミッション認識（permission-aware）
- すべてのアクションはトレーサブルで説明可能
- ポリシーはエージェントエコシステム全体に一貫して適用

**スケールへの対応**：「単一エージェントを賢くするだけでなく、組織全体で数千のエージェントをガバナンスし、一括監視できるようにすること」が次の課題。

**次のアクション**（登壇者が紹介）：
- Hands-on Lab（4 IQ を深く学ぶ）に参加
- Microsoft Build 会場のブース訪問
- GitHub のディスカッションに参加
