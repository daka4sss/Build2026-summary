## チャプター 2: エージェント AI の本質とライフサイクル（2:26頃）

### アジェンティックアプリケーションとは何か

Keiji はアジェンティックアプリケーションを「モデルを一度呼んでレスポンスを返す」ものではなく、「コンテキストと実行から継続的に学習しながら推論・行動する長時間実行システム」と定義した。

具体例として、**トラフィックスパイクの原因調査**シナリオを挙げた。

- エージェントなしの場合: 人間がダッシュボードを見て、クエリを書き、Excel を使い、仮説を立てる
- エージェントありの場合: ライフサイクルメトリクス・サポートチケット・CRM データベース・メールメッセージなどへのアクセスを与えると、「スパイクの原因は何か」という問いを受け取ってプランを作成し、ループしながら実行し、HTML レポートを生成してくれる

このためには以下が必要となる。

- 複数の能力を持つ複数モデルの協調（例: PDF パース専門モデル）
- Microsoft 365 Graph や Azure エンタープライズデータへの深いビジネスコンテキストアクセス
- メモリ・自己学習・自己改善ループ

### エージェント AI ライフサイクル

セキュアでガバナンスの効いたフレームワークの中で、**構築 → デプロイ → 運用 → 評価・モニタリング → 緩和 → 最適化** のサイクルを継続する必要があると Keiji は説明した。「一度デプロイして終わり」ではなく、顧客・データ・マーケットプレイスとともに継続的に進化させることが重要だと強調した。

### Microsoft と Anthropic のパートナーシップ

Keiji は Anthropic を「エージェント AI のリーディングカンパニー」と紹介した。Anthropic が MCP（Model Context Protocol）・エージェントスキル・Claude Code という優れたエージェントハーネスを生み出してきたことに触れ、2025 年 11 月以降、Claude Opus のようなフロンティアモデルが自律的なエージェント能力を新たなレベルへと引き上げたと述べた。

## チャプター 3: Microsoft Foundry のアーキテクチャ（6:52頃）

### Microsoft Foundry とは

Keiji は Microsoft Foundry を「セキュアでコンプライアントなプラットフォーム上でエージェントワークフローと AI ベースアプリケーションを実行するためのコントロールプレーン」と定義した。

主要コンポーネントは以下の通り。

- **エージェント作成ツール**: GitHub Copilot CLI、VS Code、その他コーディングエージェント
- **モデル**: Claude Opus・Claude Sonnet・Claude Haiku（フロンティアモデル）
- **Foundry Agent Service**: エージェントの構築・実行インフラ
- **Foundry IQ**: データソース接続（RAG やナレッジグラウンディング）
- **ガバナンス層**: Microsoft Entra（ID 管理）、Microsoft Purview（ガバナンス）、Microsoft Defender（セキュリティ）
- **デプロイ先**: Microsoft 365、Agent 365

「Foundry で構築されたものかどうかに関わらず、すべてのエージェントを Foundry の管理レイヤーから一元管理できる」と Keiji は述べた。これにより、強力なフロンティアモデルを活用しながら、Microsoft が提供するセキュリティ・コンプライアンス・ガバナンスを維持できる。

## チャプター 4: Claude が Foundry にもたらす価値（8:32頃）

Caroline が登壇し、「Microsoft がプラットフォーム・スケール・エンタープライズリーチを提供する。次の問いはその上に何を構築するかだ」と述べ、Claude が付加する価値を 4 点で整理した。

### 1. フロンティアインテリジェンス — 本当に難しい仕事への対応

「オートコンプリートや表面的な要約ではない」と Caroline は強調した。推論・コーディング・分析において、最も経験豊富なエンジニアやアナリストに任せるような仕事をモデルが担える。難しい 20% でモデルが強ければ、下流のすべてがシンプルになる。

### 2. 安全性とガバナンス — ボルトオンではなくビルトイン

Constitutional AI（憲法的 AI）に基づいてモデルが訓練されており、安全性は後付けの層ではなく訓練プロセス自体に組み込まれている。Azure 上では既存のデータハンドリング・アクセスコントロール・コンテンツフィルタリング・監査・コンプライアンスのガバナンスの中で動作する。「能力とコントロールをトレードオフする必要はない」と述べた。

### 3. 既存 Microsoft スタックとのネイティブ統合

Claude は Azure AI Foundry で利用可能であり、M365 で管理している ID とデータと連携し、GitHub Copilot からも利用できる。開発者は開発環境を変えなくてよく、セキュリティチームも新たなベンダーサーフェスを審査する必要がない。

### 4. パイロットから本番への短いパス

評価とオブザーバビリティが他のすべてと同じ場所に存在するため、5 つの別々のツールをつなぎ合わせることなく、プロンプトのテスト・自社 evals での測定・本番でのウォッチ・リグレッション検知が一箇所で完結する。「ミーティングで映えるデモと、実際にシップして責任を持てるものとの本当の違いだ」と Caroline は述べた。

## チャプター 5: Claude モデルファミリーの使い分け（11:13頃）

Caroline が Foundry で利用可能な Claude モデルファミリーの詳細を解説した。注意: トランスクリプト上に「Claude Summit」という表記があるが、これは自動字幕の誤認識であり、正しくは「Claude Sonnet」である。

### Claude Opus — 最高インテリジェンスモデル

- **用途**: 複雑な推論、大規模・不慣れなコードベースへの深いコーディング、非常に長いホライゾンのエージェントタスク
- **差別化要因**: 長時間の実行にわたってコヒーレントであり続ける能力。ゴールを多くのステップにわたって保持し、途中で問題が起きても回復し、推論の一貫性を保てる
- **最適な場面**: 明確な小タスクに分割できない仕事。また Opus 自体が大きな仕事を小タスクへ分割するオーケストレーターとして機能する

### Claude Sonnet — 推奨デフォルトモデル

- **用途**: ほとんどのエンタープライズ業務・コーディングタスク
- **特徴**: 高速、高い能力。Opus との差が十分に小さく、大多数のタスクで Sonnet から出る必要がない
- **推奨**: プロトタイプの起点として Sonnet を使う。多くのチームが「Sonnet だけでどこまで行けるか」に驚く

### Claude Haiku — 高スループットオプション

- **用途**: 低レイテンシ・高ボリュームの定型タスク（分類、抽出、ルーティング、タグ付けなど）
- **特徴**: 大型システムの下位に位置する明確に定義されたタスクに最適
- **移行タイミング**: タスクが明確に定義され、スピードとコストの優先度が上がったら Haiku へ

### 使い分けのルール・オブ・サム

1. **Sonnet でプロトタイプを始める** — アイデアが機能するかどうかを素早く確認
2. **Sonnet が苦しくなったら Opus へアップ** — 推論が本当に難しくなったとき
3. **タスクが明確になったら Haiku へ下げる** — スピードとコストが優先事項になったとき

「最大のモデルにデフォルトで手を伸ばすのではなく、ジョブにモデルをマッチさせることが目標だ」と Caroline は述べた。

### VS Code でのコード実装

エージェント「Sparkles」のコードを紹介。主要なポイントは以下の通り。

**接続方法**: AnthropicFoundryClient（Microsoft Agent Framework の Foundry SDK に含まれる）を使用。設定項目はモデル名・API キー・ベース URL の 3 点で、これらは Foundry の Details タブから取得できる。キーレスデプロイ（Managed Identity による認証）も利用可能。

**Cupcake Store MCP の利用**: 公開 MCP サーバーとして「Cupcake Store MCP」を構築。このMCPはエージェントへの指示（システムプロンプト）とツール群（注文処理・質問回答など）をカプセル化している。プライベート MCP では認証ヘッダーを渡すことで内部・外部システムへの接続も可能。

**エージェント起動フロー**:
1. MCP から指示とウェルカムバナーを取得
2. その指示とツールをエージェントに渡してエージェントを作成
3. セッションをループで起動し、ユーザー入力を待受け・MCP ツールを呼び出す対話型セッションを実行

## チャプター 7: Foundry Agent Service と Hosted Agents（19:52頃）

Keiji が登壇し、エージェントがどのように動くかの詳細を解説した。

### エージェントとハーネスの概念

エージェントはフロンティアモデル（Claude シリーズなど）を「ハーネス」と呼ばれる仕組みの中で動作させる。ハーネスはモデル推論を駆動し、コードの記述・ツール呼び出し・入力受信・処理・ループによる反復を可能にする。これが「エージェントループ」と呼ばれるものである。

### Foundry Agent Service の概要

Foundry Agent Service は Microsoft Foundry の中でエンタープライズグレードの AI アプリ・エージェントを構築・実行するためのコンポーネント。

- **オープン設計**: Agent-to-Agent プロトコル、MCP、その他の新興標準を含む各種フレームワーク・プロトコルへの対応
- **マルチエージェントワークフロー対応**: GitHub Copilot SDK、LangChain、LangGraph、Claude Agent SDK など好みのフレームワークが使用可能
- **Foundry モデルへのアクセス**: Claude モデルの呼び出し
- **データソース連携**: Foundry IQ やその他データソースへの接続
- **デプロイ先**: Microsoft 365、Agent 365 へのデプロイが可能
- **エンドツーエンドオブザーバビリティ**: 監視・最適化・改善のサイクルを支えるガバナンスの簡素化

### Hosted Agents とは

Hosted Agents はカスタムコードで構築したエージェントを Foundry Agent Service 上でホストする機能。

1. 任意のフレームワーク（GitHub Copilot SDK、LangChain、LangGraph、Claude Agent SDK など）でエージェントを構築
2. ローカルマシンで動作確認
3. Foundry Agent Service のクラウドサンドボックスへ移行

**Hosted Agent サンドボックスの利点**:
- Foundry リソース（Claude モデルの呼び出しなど）へのアクセスに必要な認証が自動でセットアップされる
- エンタープライズデータを保有するツールや MCP への安全な接続のための認証も自動で提供される

## チャプター 9: Claude Agent SDK の詳細（25:05頃）

Caroline が「個人的に最も好きなトピックの一つ」と述べて Claude Agent SDK の詳細を解説した。

### Claude Agent SDK とは

Claude Agent SDK は Claude Code を動かしているハーネスそのものを SDK として公開したもの。

- 数百万人の開発者が毎日使っている Claude Code と同じエージェントループ、同じツール群、同じコンテキスト管理を利用できる
- Python および TypeScript でプログラム可能
- 本番ハーネスそのものであり、Anthropic 自身が使っているものと全く同じものの上に構築できる

### エージェントループの基本構造

4 ステップの単純なループがすべての土台である。

1. コンテキストを収集する（Gather context）
2. アクションを取る（Take action）
3. 作業を検証する（Verify the work）
4. タスク完了まで繰り返す（Repeat until done）

「優れたエージェントを作るのは巧みなプロンプトではなく、この 4 ステップそれぞれをうまくやることだ。SDK はデフォルトでそれをうまくやれるように設計されている」と Caroline は述べた。

### すぐに使えるツール群（Out of the Box）

- コード実行（Code Execution）
- ファイルシステム（File System）
- Web 検索（Web Search）
- To-do リスト（To-do List）
- MCP（Model Context Protocol）
- カスタムツール（Custom Tools）

内部 API や独自データソースをツールとして公開すれば、エージェントが他のツールと同様に使用できる。

### ループを支えるインフラ層

多くのチームが過小評価するがクリティカルな部分として、Caroline は以下を挙げた。

| 機能 | 説明 |
|------|------|
| コンテキスト管理 | 長時間タスクでコンテキストウィンドウが枯渇しないよう管理 |
| セッションとメモリ | 作業を中断・再開できる |
| パーミッション | 許可されたことだけを実行する |
| ライフサイクルフック | 各ステップで独自ロジックを挿入でき、常に実行される |
| サブエージェント | 作業をファンアウトして並列化できる |
| エラーハンドリングとオブザーバビリティ | 何をしたか、なぜそうしたかを可視化 |

「ほとんどのチームは SDK を見つける前にハーネスを自分で作ってしまう。ループを書いて、ツールのワイヤリング、コンテキスト処理をして、パーミッションとオブザーバビリティの問題にぶつかって、気づいたら製品を作る代わりに別のプラットフォームを維持していた、ということになる。それが今や Claude Agent SDK でスキップできる作業だ」と述べた。

## チャプター 10: 評価（Evaluations）フレームワーク（32:11頃）

Caroline が評価の重要性と Azure Foundry での具体的な評価指標について解説した。

### なぜ評価が重要か

評価はプロバビリスティックな（確率的な）ユースケースに一定の決定論性を加える手段であり、早期に、かつ丁寧にセットアップすることが必要だと強調した。「すべての顧客・パートナーとの会話でいつも話すこと」として Caroline は評価の重要性を繰り返した。

### 評価の 4 つの柱

**1. 品質（Quality）**
- Groundedness（グラウンデッドネス）: 期待値にどれだけ近いか
- Coherence and Fluency（コヒーレンスと流暢さ）: モデルの応答の一貫性・自然さ
- Relevance（関連性）: 回答がどれだけ適切か

**2. リスクと安全性（Risk and Safety）**
- 安全でない・保護されていない方法でモデルとやり取りするリスクへの対応
- アングラウンデッドな情報が外に出ないための管理
- コード脆弱性の検出

**3. エージェント評価（Agentic Evaluations）**
- 意図理解（Intent Understanding）: エージェント（特にマルチエージェント構成）が意図を正しく理解したか
- ツールコール精度（Tool Call Accuracy）: ツールコールはどれだけ正確か
- タスク遵守（Task Adherence）: 完全なタスクを完了できるか

**4. カスタム評価（Custom Evaluators）**
- ユースケースに特有の評価指標を拡張できる

### 評価の実践

- Azure 上でビルトインの評価スコアが利用可能
- Azure Foundry のインターフェースとプログラムの両方から計測・評価できる
- リアルタイム評価と時系列でのドリフト検知の両方に対応
- モデルのバージョンアップやコードの変更があった際の品質比較にも活用できる

Caroline は「評価はプロセスの最後まで待たないこと。エージェントソリューションを構築するプロセス全体を通じて組み込むべきものだ」と強調した。

## まとめ

### 本セッションで示された主要ポイント

1. Microsoft Foundry は Claude モデルを含む最高のフロンティアモデルを、エンタープライズのセキュリティ・ガバナンス・コンプライアンスの中で利用できるコントロールプレーンである
2. Claude Agent SDK（Claude Code のハーネスと同一実装）により、エージェントループ・コンテキスト管理・パーミッション・ライフサイクルフック・サブエージェント・オブザーバビリティを備えた本番品質のエージェントをゼロから構築する必要がなくなる
3. モデルはジョブに合わせてマッチングすべきであり、Sonnet でプロトタイプ → Opus で高難度タスク → Haiku で大量定型処理という使い分けが推奨される
4. 評価は後付けではなく開発プロセス全体に組み込むべきで、Azure Foundry が品質・リスク安全性・エージェント特有の指標とカスタム評価を統合的に提供している

### 発表された新機能・提供状況

| 機能 / 製品 | 状況 | 詳細 |
|------------|------|------|
| **Claude Opus / Sonnet / Haiku on Microsoft Foundry** | 利用可能（GA相当） | Azure AI Foundry 上で Claude の全モデルファミリーが利用可能 |
| **Claude Sonnet 4.6** | 利用可能 | デモで具体的に使用されたバージョン |
| **Claude Agent SDK** | 利用可能 | Python・TypeScript 対応。Claude Code と同一のエージェントハーネス |

### 次のアクション（開発者向け）

1. Azure AI Foundry にアクセスして Claude モデルをデプロイし、Playground で動作確認
2. Claude Agent SDK（Python / TypeScript）をインストールし、既存のエージェントコードから移行
3. Foundry Agent Service の Hosted Agents 機能でエージェントをクラウドホスト化
4. 評価指標（Groundedness・Coherence・Task Adherence など）を早期から組み込む
5. MCP サーバーを構築して内部 API・企業データをエージェントにツールとして公開
