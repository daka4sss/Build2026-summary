## 全体像

本セッションは、Microsoft Build 2026において GitHub Copilot SDK の正式 GA（バージョン1.0）を記念し、SDK の設計思想・展開先・デモ・今後のロードマップを詳解した技術セッションである。登壇者2名のうち Patrick Nikoletich が SDK の概要・採用状況・将来計画を担当し、Steve Sanderson がライブコーディングデモを通じて具体的なエージェント構築手法を披露した。

セッションの核心メッセージは「一つのアgentic ランタイムをあらゆる場所で動かす」という一貫した哲学だ。GitHub.com・Copilot CLI・Copilot SDK はいずれも同一のランタイムハーネスを共有しており、CLI で培われたエージェント体験がそのまま SDK に持ち込まれる。GA に伴い対応言語は TypeScript、Python、.NET、Go、Java に加えて Rust が追加され、6言語体制となった。また Office Excel・Copilot Studio・Cowork（M365）など主要 Microsoft 製品への展開が進んでおり、品質ベンチマークでは一部カテゴリで 40〜50% 向上が確認されている。

Steve によるデモパートでは、不動産リード管理システムを題材にした C# と TypeScript によるエージェントオーケストレーション実装を段階的に実演した。カスタムツール登録・ビルトインツールの選択的有効化・MCP サーバー連携・プロンプトインジェクション対策としての OS サンドボックス（MXC）・仮想ファイルシステム（SessionFS）によるセッション分離と可搬性の実現など、プロダクション運用を見据えた多層的なアーキテクチャが示された。

セッションの後半では、今後 30〜60 日のタイムラインでの Visual Studio・VS Code・GitHub.com の体験統合、エフェメラルクラウド環境へのエージェントデプロイ・マルチデバイスセッション継続（Mission Control / Task Service）、オープンプラグイン標準、ユーザー設定メモリサービス、そして Node から Rust へのランタイム書き換えによる 10x 以上のパフォーマンス改善計画が発表された。Patrick は Rust ランタイムを WASM にコンパイルして Chrome 拡張機能（V8 サンドボックス内、約 500KB）として動作させるデモも披露し、「エージェントをどこにでも置く」というビジョンを象徴的に示した。

## チャプター 1: GitHub Copilot SDK の GA と設計思想（0:00頃）

Patrick Nikoletich が SDK チームの PM として登壇し、以下の要点を説明した。

- **SDK 正式 GA（バージョン1.0）**: 2025年末から開発を開始し、同年1月にテクニカルプレビューを経て Build 2026 週に GA に到達。
- **共有ランタイムハーネス**: GitHub.com・Copilot CLI・Copilot SDK はすべて同一のランタイムハーネスを使用している。つまり CLI で開発・検証したエージェント体験がそのまま SDK に持ち込まれ、逆も然り。「One Copilot」体験の技術的基盤となっている。
- **CLIサーフェスの全機能を SDK に統合**: セッション管理・ツール管理・ドキュメント・エンドツーエンドテストなど CLI の機能群を（CLI 固有のものを除き）すべて SDK に引き上げ済み。
- **展開先の拡大**: ローカル環境の個人アシスタント組み込みから始まり、現在は本番システム・内部業務アプリ・外部顧客向けシステムへと拡大。ローカルマシン・コンテナ・プライベート VNet・マルチテナントサービス・エアギャップ政府クラウドのすべてで稼働可能。GitHub Copilot サブスクリプションなしでも利用でき（BYOK：Bring Your Own Key）、任意の推論プロバイダーを使用できる。
- **対応言語の拡充**: 1月の TypeScript・Python・.NET・Go の4言語から、パブリックプレビューで Java を追加、GA で **Rust** を追加し、計6言語に。Rust の追加により将来的な全主要プラットフォーム対応の布石とした。

## チャプター 3: ライブデモ — エージェントオーケストレーションの基礎（5:37頃）

Steve Sanderson が C# によるライブコーディングデモを開始。シナリオは不動産会社のリード管理パイプライン自動化。

**デモのシナリオ**: 顧客から届く物件問い合わせメール（Web・WhatsApp などを想定）を受け取り、（1）問い合わせの妥当性検証（スパム除外）→（2）物件ポートフォリオの検索・マッチング→（3）営業担当者向けレポート生成、という3ステップのワークフローをエージェントが並列処理する。

**実装の要点**:
1. `CopilotClient` インスタンスを1つ作成してランタイムを初期化し、その中で複数のセッションを並列起動する。エージェントの概念は SDK 側ではなくアプリ側で自由に定義できる（非固執型設計）。
2. 最初はツールセットを空にして「エージェントは何もできない」状態から始める。意図的な最小権限設計。
3. **システムプロンプトのカスタマイズ**: デフォルトでは Copilot CLI と同じシステムメッセージが使われるが、数ヶ月・数年・多大なコストをかけてチューニングされた既存プロンプトを丸ごと捨てるのではなく、「Identity セクション」のような特定の節だけを置き換えることを推奨。デモでは「あなたは不動産会社のスタッフで、問い合わせ検証→検索→レポート作成のワークフローを実行する」というアイデンティティに差し替えた。
4. **カスタムツールの追加**: C# のメソッドをそのままツールとして登録。フェーズ（validation / search / reporting）と現在のインテントを状態として記録するツール、および SQL データベース検索を行う `SearchProperties` ツール（多数のパラメータで検索条件を指定）を追加したことで、エージェントが実際にデータベースを検索しレポートを生成するまでになった。
5. **ビルトインツールの選択的有効化**: Copilot CLI が持つすべてのビルトインツール（ファイル読み書き・SQL・glob 等）を一括で有効にすることもできるが、それは過剰権限になる。今回は `web fetch` ツールのみを有効化し、近隣学校の住所検索など最新情報の調査ができるようにした。デモでは「Sugar Wharf Podium School（1ヶ月前開校の新設校）の近くに住みたい」という問い合わせに対し、モデルの学習データにはない情報をウェブ検索で補完し、物件検索条件に活用した。

## チャプター 4: ライブデモ — 分離モデルとセキュリティ（16:00頃）

Steve がプロダクション運用を想定したセキュリティと分離のアーキテクチャを3段階で解説した。

### 分離モデルの概観

| モデル | 特徴 | コスト |
|---|---|---|
| 直接実行（Direct Execution） | エージェントとツールがサーバー上で直接動作。ツール制限で権限を絞れる | 安価 |
| コンテナ/VMごとのセッション | 完全分離。独立したOSとファイルシステム | 高価 |
| OS管理サンドボックス（MXC） | OSレベルで制約を設定。ファイルシステム・ネットワーク・サブプロセス制御 | 中程度 |
| 仮想ファイルシステム（SessionFS） | セッションごとの仮想FSで分離＋レジリエンスを実現 | 安価 |

### OS管理サンドボックス（MXC）のデモ

- **MXC（クロスプラットフォームサンドボックスライブラリ）**: Windows・macOS・Linux 対応の新技術。OS 自体がエージェントの行動を制限する。
- **プロンプトインジェクション攻撃の実演**: まず意図的に「何でも指示に従う」という脆弱な設定と全ファイルシステムアクセス権を付与したエージェントに、PowerShell でファイルを作れという悪意ある問い合わせを送信し、ファイル作成に成功することを示した。
- **サンドボックス適用後**: JSON 設定ファイルでサンドボックスポリシーを定義し（読み書き可能なパス・ネットワーク接続先・サブプロセス制限など）、同じ攻撃を試みると OS レベルで遮断され、エージェントが何度試みても書き込みに失敗することを実演。「プロンプトだけに頼らないことが重要。プロンプトインジェクションされてもサンドボックスが守る。」

### 仮想ファイルシステム（SessionFS）のデモ

- **Copilot SDK サーバーサンプル**（公開済み GitHub リポジトリ）を TypeScript で使用。
- **分離無効状態**: アプリは Docker コンテナ上で動作し、分離なしではエージェントがコンテナのホストファイルシステム（自分自身のソースコードを含む）を読み書きできてしまうことを確認。
- **分離有効状態**: `SessionFS`（ファイルシステム抽象化 API）を使い、セッションごとに独立した仮想 FS を提供。実装例としてインメモリ実装・オンディスク実装・カスタム実装を示した。仮想 Bash（サードパーティライブラリ Just Bash を利用）も同じ仮想 FS に紐付けることで、シェルツールもホストマシンから完全に隔離。
- **セッションの内部状態**: セッション状態は events.json ファイルに記録される。このファイルがエージェントランタイムの真実のソース（source of truth）であり、ローカルディスクにマップすることで中身を可視化できる。
- **レジリエンスのデモ**: ブラウザタブを閉じるとセッションファイルが自動削除され、同じ URL で再訪問するとファイルが復元される（バックエンドストレージへの rsync 等で実現可能）。これにより「サーバー再起動・ユーザー移動があってもセッションを継続・移行できる」本番運用に適したアーキテクチャが実現できる。
- **GitHub.com チャット機能への適用**: この仮想 FS 分離アプローチは GitHub.com のチャット機能を Copilot エージェントハーネスに移行する際に実際に採用されており、機能の有用性の大幅向上と配信コストの削減を同時に達成したとのこと。

## チャプター 5: 将来のロードマップ（30:25頃）

Patrick が GA 以降の計画を解説した。

### Visual Studio・VS Code・GitHub.com の体験統合

- 今後 **30〜60 日**で Visual Studio・VS Code・GitHub.com の Copilot 体験が統合され、差異が消えていく。同じプラグイン読み込み・スキル共有・アーティファクト共有・一貫したエージェント動作が実現する。

### リモートクラウド環境（プレビュー）

- **エフェメラルクラウド環境へのデプロイ**: SDK をローカルマシンだけでなく GitHub のエフェメラルクラウド環境上でエージェントを起動できるようになった。
- **マルチクライアント・マルチデバイスのセッション継続**: エージェントが動作している間、ユーザーはアプリを閉じて別のデバイス（スマホ・ウェブブラウザ等）からセッションに再接続できる。これを支えるのが **Mission Control** と **Task Service**。アプリを閉じてもクラウド上でエージェントは作業を継続し、任意のタイミングで指示を追加して最終的に結果を引き取れる。「デカップリング（切り離し）とポータビリティ」がキーワード。

### Microsoft 全社のエコシステム統合

- Azure・M365・W365・Xbox・LinkedIn を含む全 Microsoft 部門と「一緒に出荷する（ship together）」体制へ。
- **オープンプラグイン標準（Open Plugins）**: 最近リリース。スキル・フック・プラグイン・カスタムエージェント定義をパッケージ化し、あらゆるサーフェスで共通ロードできる1つの標準。プラグインカタログのサーフェス間共有も開発中。
- **ユーザー設定メモリサービス**: CLI でのコーディング中にエージェントが記録したユーザーの好みと事実が、サーフェスをまたいで共有される。将来的にはプロジェクト計画の引き継ぎなど、GitHub の境界を超えたコンテキスト共有に拡大予定。
- **引用（Citations）・MCP・コンプライアンス**: 情報の出所明示・準拠した情報アクセス・基幹業務システムへの容易な組み込みを継続投資対象とする。

### Rust ランタイムへの書き換え

- 現在の SDK ランタイムは Node.js ベースで、起動時に約 **130MB** の RAM を消費。
- **Rust ランタイムへの書き換えが進行中**（複数の PoC 完成済み）。期待効果: 起動時間・メモリフットプリント・バンドルサイズの **10倍以上改善**、対応プラットフォームの大幅拡大。
- **WASM へのコンパイル実演**: Rust ランタイムを WASM にコンパイルすると約 **500KB** に縮小。これを Chrome 拡張機能（V8 サンドボックス内）として動作させるデモを披露。MacBook と Windows マシンを同時に映し、ブラウザ拡張機能内のエージェントにリモートリンクで接続してブラウザを操作させるという、「真にどこにでも置けるエージェント」のビジョンを示した。

### 技術者向けの次アクション

1. **SDK を試す**: aka.ms 経由の Copilot SDK リポジトリと Getting Started ガイドを参照し、C#・TypeScript・Python などで `CopilotClient` と `Session` を使ったエージェントの基本実装を動かしてみる。
2. **OS サンドボックス（MXC）をプレビューで評価する**: 外部入力を受け付けるエージェントには必ずサンドボックスポリシーを設定し、プロンプトインジェクション耐性を確認する。JSON 設定でファイルシステムパス・ネットワーク宛先・サブプロセスを制限するポリシー設計から着手する。
3. **SessionFS でセッション分離と永続化を設計する**: Copilot SDK サーバーサンプル（GitHub 公開済み）を参考に、セッションごとの仮想 FS を実装する。本番では on-disk 実装 + バックエンドストレージへの rsync/blob store 同期によるレジリエンスを実現する。
4. **ツールセットは最小権限から始める**: SDK でエージェントを構築する際は、まず空のツールセットでスタートし、必要なツール（カスタム関数・特定のビルトインツールのみ）を選択的に追加する設計を徹底する。全ビルトインツールを一括有効化するのは避ける。
5. **Copilot Studio / M365 環境を持つ場合はプレビューテナントで SDK ハーネスを体験する**: 品質ベンチマークで 40〜50% 向上が報告されているコーディングエージェントハーネスを、非コーディングシナリオに適用することで自社業務への価値を確認する。
